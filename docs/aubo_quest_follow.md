# Quest / AUBO：跟随代码与现场验证

**2026-11-01 左 Y 一键归位（oneshot 模式）：** 操作者反馈按住式回位中途频繁中断、需多次重按。机制：按住回位的每一拍被三道闸盯着——左 Y 按钮状态 200ms 新鲜度（`home_hold_active` max_age_s=.2）、反馈 200ms 新鲜度、发送间隔预算，任何一道跳即取消归位；输入链路偶发空档使第一道成为最高频中断源。新增 `--home-trigger {hold,oneshot}`（**默认 hold=旧行为逐字不变**）：oneshot 下**按一下左 Y 即锁存归位目标**，松开/输入 200ms 空档不再撤销；**再按一次左 Y 主动中止**（仅 moving 态；ready 态按下=开始，web 预备流程不受影响）；**Grip 释放与 worker 故障照旧停止**；速度 20°/s、加速度 6°/s²、0.15° 容差、回位期间录制挂起全部不变；1.0s 输入超时（全失联兜底）保留并经 USB 直连复核（实测空档 ≤15ms，几乎不触发）。已知保留：反馈 >200ms 过期仍会以 failed 取消归位（既有安全设计：无新鲜反馈不给运动许可），重按即续。实现：quest_follow.py `home_trigger` 模式分支（freshness 门槛、hold_end 事件、二按中止、中止/完成后清 `_home_button_requested` 防陈旧 offer），status 录制元数据含 `home_trigger`。验证：tests/test_aubo_home.py 27 项（20 hold 回归 + 7 oneshot：输入空档/松开不撤销、二按中止三按重启、无按住完成归位、故障仍取消、状态上报 trigger）；全套离线回归笔记本 313、车载 313 项全绿；车载两个启动脚本（run_sixaxis_vehicle/30min）已带 oneshot。

**同日跟踪误差修订（现场首用实跑后）：** oneshot 首用暴露真正的高频中断源是 `home_tracking_error`（50 次归位事件中 10 次中断全部是它，非输入/反馈类）：录屏数据实测目标斜坡只跑 4.2°/s（名义 20°/s）——worker 的 dt=min(周期,实际间隔) 封顶在 SDK 双峰应答节奏（一半周期 70-130ms）下吃掉 ~60% 步进；臂实际 2.9°/s，差距以 1.2°/s 稳定增长，3° 容差 2.5s 内必撞线；79.9° 归位曾 7 次中断 29 秒。修复：①归位跟踪容差 3°→**8°**（新常量 `HOME_TRACKING_ERROR_RAD`，柜端真卡死时 20°/s 流式下 0.4s 仍触发，保护保留）；②worker 归位步进 dt 封顶 周期→**3×周期**（`bounded_home_step` 内部上限 0.05→0.12s，长停后单步跳变仍 ≤2.4°/轴）。预期一次按下完成全程归位（79.9° 约 8-12s）。柜端 P2P（robotServiceJointMove，徐灿"返回果箱"同款）列为后续升级项。验证：双侧 313 项全绿。

## 当前边界与复用

复用原 vr-teleop-kit 网页、腕部校准、滤波、离合、目标管理和解耦 IK，保持 `world` 默认、HMD yaw 关闭。没有改作者求解器，也没有 ROS、上电、归位、清错、夹爪或采集接入。原只读入口继续只加载 `_aubo_readonly`，不存在切换成运动的网页开关。

新增的协调代码集中在：

- `teleop/aubo/native/follow.cpp`：一个串行 SDK 实例，提供默认 J6 跟随或显式六轴跟随、原始反馈、已测慢停和原子撤销。J6 模式固定 J1–J5；六轴模式逐轴检查控制柜范围、反馈与权限，直接传递IK关节角；目标/反馈差仅用于诊断，两种模式不能混用发送 API。
- `teleop/aubo/follow.py`：SDK 唯一工作线程和独立本地 watchdog；最新目标、时效、停止确认、失败锁存。发送步长限制只在独立旧 J6 入口保留。
- `teleop/aubo/quest_follow.py`：把既有候选链路接到该 worker；网络线程在 Grip 释放、无效帧、参考空间变化、断连时立即撤销本地发送许可。原 fake-only 会话不解除限制，不调用 fake dispatch。
- `teleop/aubo/quest_preview.py`：抽出共用的 Relay/桌面循环，增加仅影响候选的速度参数。两入口复用它，不复制一套网页或 IK。

链路为：

```text
实体右手柄 → 原 WebXR/Relay → 原作者核心 → 六轴 IK 候选
  → 按入口选择 J6 投影或完整六轴，约束到控制柜本次返回的关节范围
  → 最新目标槽 → 六轴在20Hz期望节拍直接发送最新IK关节角（无主机位置步长整形）
  → AUBO FollowModeJointMove → 控制柜

控制柜 → 关节可选 SDK 路点推送，运动状态由同实例串行查询 → 有效反馈 → 显示、实际状态建锚、停止检查
Grip释放/输入故障 → 立即本地撤销 → SDK owner 请求慢停 → 反馈确认
  → 正常释放：停稳后下一次按下即可；故障停止：停稳后先释放再按下
```

选择 `--execute-j6` 时，仅取 J6 是实体联调限制，因而平移手柄不会让大臂移动；世界系旋转的某些方向也可能主要改变被屏蔽的关节。青色模型显示投影后的 J6 期望目标，实际提交目标可能更靠近实测位置，必须单独查看状态。

## 状态字段

- `mode`：`aubo_readonly_preview` 为只读；`aubo_j6_supervised_follow` 才是本阶段实体入口。
- `motion_available`：入口是否具备实体发送能力，不表示当前在运动。
- `candidate_q_rad`：当前屏幕候选。只读时为完整 IK；J6 实体入口时为只取 J6 后的期望目标。
- `hardware.last_attempt.generated_q_rad`：原作者六轴候选；`requested_offset_deg` 为此次拟提交 J6 偏移；`sdk_result.target_rad` 为实际送入 SDK 的六关节目标。
- `hardware.last_attempt.outcome`：请求在途、SDK 接受或拒绝。返回成功不表示到位。
- `hardware.joint_range_deg`：本次控制柜 J6 绝对限位；`offset_range_deg` 是换算到启动角度的相对范围，可能不对称。`range_source` 标明取自控制柜，不是人为固定幅度。
- `measured_q_rad`：真实反馈；`hardware.last_snapshot` 保留关节与状态查询原始返回和时间。
- `hardware.last_stop`、`stop_confirmed`、`stop_result_unknown`：区分停止请求返回与反馈检查结果。
- `clutch_state`：`stopping` 为停止中，`ready_to_engage` 为可按下接合，`release_grip` 为需要先释放，`engaged` 为已接合，`fault` 为硬件严重故障。桌面 `/aubo` 显示相应中文提示。
- `hardware.stop_confirmed_monotonic_s`：反馈停止确认的主机单调时间；`stop_requires_post_confirm_release` 区分正常离合与需要确认后释放的故障恢复。
- `hardware.target_policy=direct_ik`、`host_target_rate_limit_deg_s=null`：六轴直接发送范围内最新 IK 角度，无额外主机目标推进限速。
- `hardware.sdk_profile_policy=sdk_unmodified`、`sdk_profile_writes=false`：六轴不主动重置/写入 SDK 速度、加速度。`sdk_client_speed_deg_s`、`client_acceleration_deg_s2` 为 `null`，避免把历史试验值误当当前配置。
- `hardware.sdk_profile_readback`：六轴正常运行时为 `source=not_read_six_axis_unmodified`，速度/加速度数组为 `null`，因为这条 SDK 客户端内存读回既不是柜端查询，也不参与六轴直接 IK Follow。显式 `--inspect-profile` 或旧 J6 路径才会出现 `source=sdk_client_memory_not_controller_settings` 的客户端内存读回；它不证明物理执行速度或示教器配置继承。
- `xr_input`、`quest_input_fresh`：手柄位姿、Grip 和输入时效。`relay_connected` 仅代表电脑到 Relay 连接。

实体入口不使用 `candidate_sent_to_robot=false` 来暗示没有实体命令，该字段为 `null`；依据 `hardware.last_attempt` 判断实际提交。

## 实验参数与停止能力的准确含义

历史 J6 阶段曾使用 2°/s、SDK 客户端加速度 5°/s²（实验配置，不是厂家最大额定值）。当前保留的独立旧 J6 代码参数为 10°/s、5°/s²；正式六轴入口不再写入这组参数。正式六轴当前期望发送 20 Hz，独立旧 J6 保留 10 Hz；实际间隔受同步 SDK 耗时影响，不补发历史目标。客户端内存读取值不能独立证明控制柜执行的硬限速。

新增联调阈值均是显式实验配置，不是厂家保证：输入年龄 250 ms、候选年龄 100 ms、跟随发送及普通查询预算 500 ms；阻塞式慢停完成单独使用 2 秒预算。独立 J6 入口要求 J1–J5 反馈偏离启动测量不超过 0.1°；六轴无此固定要求。关节反馈监视允许控制柜范围外最多 0.1°的读数容差，但命令和重新接合不允许越过控制柜上下限。目标与反馈差继续记录，当前无主机差值停止阈值（历史1°/3°试验见文末）；独立 J6 入口仍由 Python 与原生层核对发送步长；六轴入口取消该项，并保持 SDK 客户端运动参数不写入、不重置。

停止请求使用已经实测过的 `rootServiceRobotMoveControl(RobotMoveStop)`。慢停完成使用独立 2 秒试验预算；返回成功后，再最多观察 2 秒；此阶段的只读查询共享这段剩余时间，运动阶段普通查询仍使用 200 ms 预算。查询结果超过确认总截止时间，或关节/状态接收时间在使用时超过 200 ms，均不能用于确认。要求停止状态且一段至少 100 ms 的关节变化不超过 0.02°，才记录反馈层停止确认。停止完成超预算依然锁定恢复并提示现场停止；如果稍后返回成功，仍检查反馈，以区分“迟到但已确认停止”和“停止结果不明”，不会因确认停止自动解除严重故障。串行慢停期间不提交目标，反馈过期不能用作新锚点，也不伪报为另一次输入故障。这些反馈条件仍须与现场观察共同评估，不能代替急停或碰撞保护。

**尚无独立物理停止通道。** 同一个 SDK 实例串行工作；独立 watchdog 能在阻塞期间撤销许可、丢弃候选、锁住恢复，但实际慢停只能等在途 SDK 调用返回后发送。不能通过新线程假定 SDK 支持并发，也不能声称断网后必停。超时状态明确提示 `operator_stop_required`。
