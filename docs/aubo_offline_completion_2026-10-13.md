# 离线问题修正与接口补齐记录

日期：2026-10-13。已实现并验证本轮可在离线明确完成的代码工作：审查问题R1/R2/R3/R4、AUBO关节模型映射、显式坐标FK对照、只读有限采样和作者核心/假会话组合协调。没有访问真实设备，不能据此宣称真机连续控制完成。

## 改动与原因

| 内容 | 实现及验证 |
| --- | --- |
| R1 时间戳异常 | input/offer转换失败直接撤销pending、退出接合、锁住恢复；复现中的后续dispatch现在拒绝 |
| R2 缓存策略 | 不可解析/未来/非有限时间使反馈失效；合法较旧包丢弃并保留新样本；只读层对验证失败保守失效 |
| R3 原始证据 | 查询返回值保留SDK返回码/数据/时间，另附feedback_validated和validation_error；探测失败且不自动FK或继续采样 |
| R4 录制 | 默认仍OFF；显式自动录制实际位于/data/VR_teleoperation_runtime/recordings/mujoco；自定义目录解析后也要求在/data |
| 目标顺序 | 同会话的重复/迟到候选不覆盖较新目标，长停顿不扩大跳变预算，响应未知不重试 |
| 假停止失败 | 撤销先于假stop，失败记入stop_error并锁住会话；重新松开/按Grip不能解除，需要新建会话 |
| 模型接口 | 按名称映射六臂关节，其余qpos为显示模板；未宣称实机关节方向/零位已核实 |
| FK对照 | 保存SDK FK输入关节；离线使用明确A/B变换及来源比较同组q下的位姿，无隐式TCP/基座假设、无猜测验收阈值 |
| 只读有限采样 | 用户显式指定次数/主机间隔，串行Get，失败即停；统计主机接收间隔，不把它当控制柜采样率 |
| 作者核心协调 | 复用QuestTeleoperator，不改作者IK；缓存有效反馈锚定、故障恢复需松开再按、立即撤销无效输入、屏蔽摇杆归位；不自动连接网络/运动/开爪 |

`AuboShadowCoordinator`只生成inspectable Candidate；`dispatch_fake()`只会发送到构造时内部建立的FakePositionBackend。读取只读follower缓存后，测量来源保留为aubo_readonly，不会因假发送更新实测状态。关闭后对象不能重新激活。

协调器检查epoch/seq/t_client和右手姿态/按钮；断流后即使下一帧到达，也不能用它刷新时间来掩盖已发生的超时。参考空间重置帧不能同时算作“用户已松开Grip”。常规Grip释放正常取消，下一次按下从新反馈重新锚定。模型/核心异常先撤销目标再传播异常。

## 仍须按设备依据实施的接口

1. SDK推送回调/设备事件与回调生命周期；当前只读是有限Get采样，没有推送或后台轮询服务。
2. FollowModeJointMove真实绑定与发送调度；控制柜目标覆盖/积压语义和推荐周期仍待确认。
3. 真实stop/断开/在途请求协调及独立watchdog；当前协调模块单调用者驱动，不是线程安全真机运行时，假stop不能证明物理停止。
4. 当前设备的工作限位/速度/加速度/误差及超时；SessionPolicy要求调用者显式提供，无实机默认配置。
5. RG RS-485独立执行与反馈；退出扭矩未决定，没有启用串口或复制禁用扭矩行为。
6. 真实相机及LeRobot薄接口与采集对齐。

本轮没有为了“补全”猜测这些接口行为，真实运动仍不可用。下一阶段可以先接机执行只读核对；得到模式/固件/工具/范围资料后，才完善无Quest的跟随/停止验证入口。完成后再接回作者核心。不会自动发RG_READY或把模型显示状态当作真实反馈。
