日期：2026-11-12，北京时间。本文结合本地源码、已有验收文档和本次用户确认整理。此次没有连接机械臂、相机或车载电脑，没有更改控制参数、录制行为或既有数据。

> 2026-11-13 最新频率修订：根据用户进一步讨论，首版改为 **30 Hz 数据集状态/动作时间轴 + 30 Hz 策略动作执行 + 三路相机各 30 fps**，每步约 33.33 ms；替代此前 25 Hz 和 50/30 的方案建议。模型完整推理频率单独确定，底层 200 Hz/5 ms 路点不变。

> 2026-11-15 状态修订：阶段A–D现已形成真实采集、LeRobot v3导出、QA和只读回放闭环，且已完成恢复副本上的三路真实数据逐帧验收。当前设备/录制/控制诊断/策略冒烟结论见[正式数采基线](aubo_collection_baseline_2026-11-15.md)；下文“待实现/未联机”等是2026-11-12/13的计划阶段记录，不代表现状。

## 1. 目标及已明确的约束

最终目标是：通过 Quest 遥操作采集番茄串真机示范，以 LeRobot 管理训练数据，微调 π0.5，使策略完成 **接近 → 果梗对准 → 夹持剪断 → 携串退出 → 搬运 → 释放**。

本次用户明确：

- 使用已有夹剪一体工具，其功能此前已验证正常。不能再把“工具尚未安装/不能开合”的历史描述作为现状。
- 第一版目标就是全流程策略，搬运和释放同样属于学习范围，不能默认交给固定 placement 宏动作。
- 有两台 L515 场景相机，均观察同一侧工作区，不是分别负责两个作业区。
- 腕部相机为 D405，近距离能看清果梗。当前无法接真机，实际接入与联合运行测试留待现场。
- 新增录制、视频、训练集、模型和检查点优先实际存放于 `/data`；不迁移旧目录或改已有软链接。

需分别保留三个概念：工具功能正常、相机近距离可见、整套系统在当前运动基线下联合工作正常。前两项已有用户确认，第三项仍需现场验证。

## 3. 必须优先解决的四个数据缺口

### 3.1 新批量控制路径与旧导出协议不一致

源码定位：

- `teleop/aubo/follow.py::_fixed_tick_send` 将批量结果写入 `_diagnose('send_returned', ...)` 和 `last_attempt`，该方法没有写入 `recorder.record('sdk_command', ...)`。
- `_diagnose` 写的是独立诊断流，不自动桥接到 `RawRecorder` 的 `sdk_command` 流。
- `teleop/aubo/export_lerobot.py::segments` 只从 `sdk_command` 返回事件取动作，还要求 `outcome == 'sdk_accepted'` 等旧协议字段；不会使用快照中的 `last_attempt` 重建批量动作。
- Native 批量结果已经提供 `points_rad`、`tick_s`、`clock_sent_points` 等信息，但旧导出器只识别单个成功回执目标。

因此，**新控制基线加上 `--record` 不等于已得到可按旧规则导出的动作数据**。这是一项源码可见的协议缺口；本次没有用真机试录来判定具体损失量，也没有修改实现。修复时需要同步覆盖实时记录、原始 schema、导出规则和回归验证，不能只改一处字段名称。

### 3.2 当前导出没有视觉和工具动作

`recording.py` 的 manifest 仍标为 `state_action_only`、`cameras={}`。导出器仅生成六维 `observation.state`、六维 `action`，且 `use_videos=False`。已有工具原始记录不等于工具维度已进入训练数据，相机独立 AVI 也不等于 LeRobot 已关联到正确会话。

需要建立统一 session 标识、各相机帧索引、时间映射和多模态导出，生成真正能够被 π0.5 读取的图像/状态/动作样本。

### 3.3 全流程任务与旧筛选规则不一致

旧导出只保留 `control_source=teleop`、`hardware_state=active` 且未暂停的片段，排除 home/placement。新执行器也只允许普通 teleop 目标进入当前透传路径，历史一键归位/放置不能直接视为本基线已有能力。

全流程数据必须保留搬运、容器上方对位、开爪和释放后确认。即使人工操作时借助宏动作，也必须完整记录其动作与观测、明确来源，并保证所学动作能在策略部署时由同一接口表达。第一轮建议人工遥操作完整流程，减少宏动作来源差异。

### 3.4 Grip 暂停不能与真实任务静止混为一类

既有用户约定是暂停片段排除；当前录制器暂停时停止状态快照，旧导出在 pause/resume 处分段。这一旧行为不在本次擅自修改。

但新全流程任务需要重新定义：

| 情况 | 新协议建议 |
| --- | --- |
| Grip 松开后机械臂仍在平滑制动 | 原始观测、底层路点与模式继续记录；不能把它标为瞬时停稳 |
| 停住等待夹剪完成、观察果串、确认释放 | 属于真实任务行为，保留图像、工具变化及明确的保持动作 |
| 操作者换握/重锚定，任务与物体基本静止 | 原始记录保留，训练导出按有据可查的分段或掩码处理 |
| 跟踪丢失、通信故障、状态无效、停止结果未知 | 标为异常，隔离或切段，不把它伪装成正常保持动作 |

恢复后的动作块不得无痕跨过暂停缺口。训练窗口不能在重锚定前后直接拼接；每段都应保留原始任务及 episode 关联。若采用 masked training，需实现对应 loader 和损失，不能只在日志写一个 mask 就认为 π0.5 会自动处理。

## 4. 推荐冻结的数据与控制协议

以下为实施建议，还不是已经执行的控制变更。

### 4.1 先固定策略接入点，再定义 action

推荐策略继续复用现有平滑规划与执行层：

```text
人工示范：Quest → 映射/IK → 已准入关节目标 → 轨迹规划/5ms路点 → TCP2CAN → 机械臂
策略部署：三相机+实测状态 → π0.5 → 同语义关节目标 → 同一规划执行层 → 机械臂
                                                     └→ 工具绝对目标 → 串口驱动
```

推荐第一版训练 `action` 使用 **被统一动作接口接受、随后交给规划器的六轴绝对关节目标 + 工具绝对目标**，关节单位 rad。采样时保留当时有效的目标及其接受时间，不能用任意未被接纳的 IK 候选代替。离线导出不引入未来才收到的输入。

这里的“输入”指模型观测：`obs_t` 不能混入 t 之后才可用的图像或状态；监督用的动作块可以包含此后相应执行时段的示范动作。动作第 0 步的时间锚点、采用规划器入口还是下游路点、推理与执行延迟需要在训练/部署协议中明确，不能把“最近成功回执目标”自动视为正确监督标签。

同时保留所有实际 SDK 批量路点与实测关节用于执行审计，但不把它们与规划器输入混作同一个 action 字段。若改选“底层参考路点”为模型动作，必须另做执行适配与资格验证；直接把已平滑路点再输入现有规划器，会产生训练/部署差异。

按 2026-11-13 用户提出的选择，目标数据集采用 **30 Hz** 状态/动作时间轴，每步约 **33.33 ms**；三路相机各采集 **30 fps** 原始图像。需要用小样本回放检查 30 Hz 的目标保持、实时快照节拍、三路图像年龄及任务精度，达标后冻结 v1。5 ms 路点与完整事件照常保留，便于后续重新导出。30 Hz 数据行不保证每秒 30 次新鲜且同步的相机或关节测量，200 Hz 底层路点也不要求变更。

### 4.2 建议字段

| 字段 | v1 建议 | 说明 |
| --- | --- | --- |
| `observation.images.scene_left` | L515 RGB | 左侧安装视角，观察同侧工作区 |
| `observation.images.scene_right` | L515 RGB | 另一场景视角，非另一作业侧 |
| `observation.images.wrist` | D405 RGB | 保留果梗、剪口、工具与果串的接触信息 |
| `observation.state` | 实测 J1–J6 + 工具位置 | 如果工具为单执行器，基本状态可为 7 维；实际维度以接口表冻结 |
| `action` | 六轴绝对关节目标 + 工具绝对目标 | 单执行器时可为 7 维；若工具还有独立执行量则按实际增加 |
| `task` | 完整任务指令 | 如“采下工作区内指定的成熟番茄串，并放入收集筐中。” |
| 业务标签 | 阶段、尝试、结果、接管 | 保存为可追溯元数据或 sidecar；首版不默认全部输入模型 |
| 质量标签 | 图像/状态年龄、失帧、缺失、命令来源、恢复 | 支持离线审计、筛选和版本对比 |

状态读数与动作目标不能混淆：工具“实测位置”和“期望开闭”分别保存。原始 pulse、标定上下限、电流、到位、硬件错误等继续留在 raw 层。

模型工具输出应为绝对目标，例如 `0=open, 1=closed`，阈值、迟滞和到位行为在适配器中冻结；不要学习“再切换一次”的按键脉冲，否则长按或动作块重复输出会导致反复开合。仍按已有单执行器夹剪联动机制执行，不凭空增加独立剪刀控制量；实际联动顺序、夹持后保载及释放映射需随工具配置记录。

如进一步使用关节相对动作训练，应以同一观测状态为基准转换并保存逆变换，重新计算对应统计量；这是训练配置选项，不修改 raw 的绝对量。π0.5 不要求真实机械臂具有 32 个动作维度。

### 4.3 图像、状态和动作的时间轴

- 同机进程统一使用主机 monotonic 时间；各条流保留 session/boot 标识，不跨机器或重启直接比较 monotonic 数字。
- 相机记录设备帧号、设备时间、时间戳域、主机接收时间、视频帧索引。当前主机接收时间并不是曝光时刻，设备钟到主机钟的映射作为校验信息保留。
- 已有双 L515 测试记录设备钟约 0.4% 漂移，不能直接把两台设备时间当成同一时钟；D405 需单独测量，不继承 L515 的拟合参数。
- 定义策略决策 tick；输入只用该 tick 之前已可用的图像和反馈，记录各自年龄。30 fps 相机到 30 Hz 数据通过带时间戳的因果前值选帧实现，不简单按帧号配对；相邻数据行允许共用同一张原始图像，并保留原帧号与年龄。读取最新帧应非阻塞，不能因等待某路新图阻塞数据循环。
- 分别报告每路图像年龄、两相机/三相机选帧时间差、关节反馈年龄、工具反馈年龄、目标接受/SDK提交/估计执行时间。SDK 成功回执不是已执行证明。
- 对 SDK 提交及缓冲账本保留时序；90 ms 是名义参考缓冲，约 99 ms 是某次参考与反馈的最佳平移估计，都不应直接硬编码成所有模态的标签偏移。
- 不能只把全体图像一律平移 100 ms 来“修好对齐”。训练和部署应复用同一观测构造、动作接口与节拍；额外延迟补偿需有回放或实测依据。
- 缺图、过期、重锚定及故障处按明确规则拒绝、切段或使用已实现的掩码，不复制旧画面并隐瞒其年龄。

30 Hz 数据每步约 33.33 ms，相机各为 30 fps，名义周期相同，便于统一时间轴；三台相机与主机并非硬件同步，仍需按时间戳选帧，偶发跳过或重复图像必须可追溯。保留原始 30 fps 视频与逐帧时间戳，按标准 LeRobot writer 在 30 Hz 网格提交选定图像；直接引用原始视频时也应验证 reader 的时间戳与容差，不靠帧号强行配对。

关节和工具反馈同样按真实频率保存；30 Hz 行使用最新有效测量并保留接收时间、原样本标识和年龄，不制造独立测量或事后未来插值。30 fps 相机理想选帧年龄约在一个相机周期内，但这不是带传输/曝光/调度后必然满足的指标。现有 200 ms 状态年龄阈值是旧导出底线，不能直接当作果梗精细剪切的数据质量目标。先测分布，再冻结数值门槛和验收集。

### 4.4 三层存储

```text
raw 原始记录：视频+帧索引 / 输入 / 实测状态 / 已准入目标 / SDK批量路点 / 工具 / 事件
    ↓ 离线完整性检查、时间对齐、任务分段、质量筛选
LeRobot v3：图像视频 + observation.state + action + task + 来源与质量信息
    ↓ 固定训练划分、图像预处理、归一化与动作适配
π0.5：训练配置、统计量、检查点、评估结果
```

建议在独立的新顶层数据目录 `/data/tomato_harvest/` 下使用 `raw/`、`datasets/`、`training/`、`evaluations/`；这只是目录建议，本次不创建、不搬动既有数据。若根目录权限不足，请用户创建该顶层目录，不借其他项目目录规避权限。

raw 尽量不可变，导出使用新目录与版本号；保存源码版本、控制基线、SDK/工具配置、相机序列号与安装、标定、导出版本和数据清单。重要原始数据另做副本及校验和。现有相机短录脚本默认会写 `~/camera_test`，后续运行应显式指定 `/data` 下 `--out`，或在获得实施任务后修正默认路径。

LeRobot v3 使用 Parquet/视频分片和 episode 元数据，不能假设“一段示范一个 MP4”。必须用真实 writer 完成 `finalize()`，随后重新打开整个数据集验证。

## 5. 全流程示范如何组织

### 5.1 任务边界

建议一个 raw 任务 episode 对应 **一串番茄的完整作业**：工具处于已知状态、目标在规定工作区 → 接近 → 对准 → 夹剪 → 撤出 → 搬运至筐 → 释放 → 可见地确认结果。最终画面与状态必须保留，不能在开爪指令发出瞬间结束。

允许对同一串进行正常重试，并在内部记录 `attempt_id`。更换目标串、故障重建会话或人为重新布置植株后，应结束/另开 episode。必要的控制暂停可对应多个训练 segment，但必须映射回同一个业务 episode；segment 不能被统计为额外的成功采摘。

归位若只是下一轮准备，可留在 raw 并标为 reset；第一版学习边界截至成功释放确认，不强行让策略学习每次实验布置与人工清场。固定起始区域及容器位置是首批数据的可接受范围约束，之后再扩大。

### 5.2 业务事件及成功标准

建议最小事件字典：`target_selected`、`aligned`、`tool_close_requested`、`tool_closed`、`cut_confirmed`、`clear_of_plant`、`at_container`、`tool_open_requested`、`released_confirmed`、`episode_result`，另附 retry、drop、damage、wrong_cut、human_intervention。

`tool_closed` 可来自工具反馈；`cut_confirmed`、`released_confirmed` 等业务事实在初期允许人工结合视频标注。不要以夹爪到位、SDK 返回 0 或“已保存”替代任务成功。

完整成功建议要求：目标果串分离、持稳撤出、运至指定收集筐、果串确实释放入筐。掉串、误剪邻近枝条和损伤分别记标签，并明确是否计入成功；报告完整成功率时写明口径。

### 5.3 按键及失败管理

保留既有录制管理习惯：左摇杆左为作废重录/开始新循环，右为保存结束当前循环，上为结束会话，右摇杆按下为标记；右 Grip 控制离合，右 Trigger 切换工具，右 A 为精细操作。

**保存只是数据完整性状态，不代表作业成功。** 不建议为了标注再堆复杂组合键，初期可用现有 mark 与离线视频标注。左右手柄 X/Y 的宏动作属于历史功能与模式依赖，当前透传采集入口需显示真实可用性，不能沿用旧页面文案指导操作。

数据保留建议：

- 顺畅成功及合理纠偏后成功的示范：进入首轮行为克隆候选。
- 自然任务失败：保留 raw、视频和原因，做失败分析；并非不加区分地把全部失败动作当正向监督。
- 硬件故障、未知停止、明显错配、丢记录：隔离并阻止进入干净训练版本。

不得把重试全部作废以只剩理想轨迹，也不得把安全但无效的长时间停顿无限重复写入训练集。目标是保留有意义的纠偏和真实等待，控制各阶段样本权重。

### 5.4 数量和划分

先采 **10–20 个完整循环**作为工程试采，覆盖至少成功、重试、暂停恢复及一次受控结束。目的是找协议和时序问题，不是承诺这些样本足以训练成功。

链路通过后，可把 **100–200 条有效完整示范**作为首轮实验预算，按初始策略结果决定增量；该数量是项目规划建议，不是 π0.5 的数据要求或成功率保证。优先覆盖果串位置/高度/尺度、果梗方向、遮挡、照明、携串摆动、接触纠偏及容器中不同落点。第一批保持设备、相机安装和作业范围稳定。

训练/验证/最终测试按日期、采集场次和植株/果串身份分组，避免同一串的重试或相邻视频片段跨集合。可采用约 80/10/10 的组级划分；量少时优先保证独立验证与测试组，而非机械追求帧数比例。归一化统计只用训练划分，不用最终测试数据调参。

## 6. π0.5 训练与部署路线

### 6.1 优先选 LeRobot 原生训练

建议首轮使用已经存在的 `/data/lerobot` pi05 实现，锁定源码提交、依赖和基础权重版本。理由是已有 v3 数据写入基础和本地 pi05 代码，可先减少跨框架数据适配。仍需验证实际环境依赖，不能把目录存在当成训练可用。

优先通用 `lerobot/pi05_base`，不要直接照搬 LIBERO 的状态维数、动作维数、相机 key、归一化或训练超参数。官方文档说明支持自定义数据和相机字段适配，默认状态/动作归一化需要 `q01/q99`。本地配置默认动作块与执行步数均为 50，需要显式审查，而非无意识照用。

OpenPI 可作为另一条训练路径，但“LeRobot v3 格式”并不自动证明任意 OpenPI 提交都能读取；若选择 OpenPI，先验证其锁定版本能加载真实数据、生成 batch、映射 AUBO/工具并往返解码，再决定正式路线。

### 6.2 第一轮训练前必须跑通的最小闭环

1. 一段真实完整示范导出后重新加载，核对三路视频、工具动作与任务结尾。
2. 检查 batch 图像、关节与工具维度、单位、camera map、task、序列边界及 action 时间步。
3. 生成训练集统计，验证 `q01/q99`、常量维、二值工具范围与夹剪少数事件；检查 resize/crop 后果梗仍可见。
4. 用少量 batch 完成前向、反向、保存和重载，再做小数据过拟合检查；loss 下降只证明部分流程可训练。
5. 推理解码回真实关节/工具单位，使用同一动作接口在无运动环境检查输出范围、节拍和控制权撤销。
6. 才进行首轮完整训练与实体策略验收。

原始视频保留可用分辨率，模型分辨率按所用配置固定；本地 pi05 默认 224×224。不能因为原视频能看清果梗，就假定缩放后的模型输入仍保留足够细节。必要时调整视角或固定裁剪策略并同时应用于训练与部署。

### 6.3 执行节拍与算力

30 Hz 下动作块 50 步覆盖约 **1.67 秒**，但不等于应当 1.67 秒才看一次新图，也不要求模型每秒做 30 次完整前向推理。预测长度、实际每次执行步数和重新推理频率分别配置，接触与夹剪阶段尤其要验证时延影响。

先确定能实现的无运动推理延迟、三图预处理时长和端到端控制预算，再选择短执行窗口、异步动作队列或 RTC。动作块必须按策略时间推进，不能把块中所有点塞入“最新目标覆盖槽”导致只剩最后一点；也不能让模型绕过现有规划器直接高频发 SDK。

现有车端硬件历史记录为 RTX 2060 6 GB、约 8 GB RAM，不能预设能满足 π0.5 常规本地训练/推理。优先规划独立训练 GPU；推理机位置根据真实测量决定。若异机推理，原始采集仍在车端本地完成，策略请求/响应单独记录观测年龄和网络时延。

训练采用全量、动作专家微调还是 PEFT/LoRA，由实际 GPU、库版本和小样本试验决定。本地 pi05 有 PEFT 适配代码，但尚未在本项目实际训练验证，不承诺某档显存必定足够。

### 6.4 部署次序与评估

部署依次通过离线回放、无运动影子推理、替身执行器、空载小范围、完整真实采摘。人工接管或撤销要清理旧动作队列，恢复时重新建锚，不追赶旧动作；对工具目标单独保留原有到位/故障语义。

核心评估同时报告：完整采摘放置成功率、首次成功率、重试次数、含重试总时间、对准/夹剪/搬运/释放阶段成功率、掉串、损伤与误剪、人工接管、策略延迟及执行异常。独立真实任务成功优先于训练 loss 或挑出的成功视频。

## 7. 下一阶段工作顺序与验收出口

| 阶段 | 现在/现场 | 工作 | 完成标准 |
| --- | --- | --- | --- |
| A：数据接口冻结 | 现在可做 | 明确规划器输入动作、工具目标、30 Hz 数据与策略执行/30 fps 相机、时间轴、暂停规则、episode 与成功标准 | 一份逐维可机读 schema，训练与部署使用同一解释 |
| B：离线实现 | 现在可做 | 新批量命令录制桥接、连续观测/工具记录、三相机会话管理、多模态导出、质量报告 | 合成与已保留日志覆盖边界；真实 LeRobot writer 能读回测试产物；既有控制回归不退化 |
| C：现场联合验收 | 下次接机 | 三相机预览/录制、工具、45档或回退档遥操同时运行；核对 TCP、负载、净空、D405 线缆及带串范围 | 三路可见且无不可解释缺口；录制无溢出；控制稳定；对齐报告及抽检视频通过 |
| D：完整试采 | 现场 | 10–20 次完整采摘、搬运、释放及纠偏 | 每条能回溯原始流，成功/失败有依据，模型输入能看清关键过程 |
| E：训练小闭环 | 数据返回后 | 少量 batch、保存/重载、小数据检查、无运动推理适配 | 维度/单位/统计/节拍正确，能走到统一动作接口 |
| F：正式采集与策略迭代 | E 通过后 | 首轮有效示范预算、独立测试集、真实策略评估及针对性补采 | 用固定评估协议确认改进，保留每轮数据和模型版本 |

当前最值得优先投入的是 A、B。继续优化手感可作为独立分支，但不应替代完整数据闭环，也不为本轮采集重新推翻已验收的 11 月 12 日控制基线。
