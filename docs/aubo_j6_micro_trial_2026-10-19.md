# AUBO 真机 J6 微动与慢停：两次实验记录

2026-10-19。用户明确要求直接进行真机测试，并确认在现场可急停。执行前已说明本次动作和实验限幅。本轮没有扩展假后端，没有启动 Quest、ROS、夹爪或持续 Logger。

## 本次动作

独立程序登录当前控制柜，从当时实际关节角建立目标，仅 J6 正向增加 1°；J1–J5 的目标保持为同一组实测角。客户端设置六轴速度上限 0.5°/s、加速度上限 1°/s²，发送一次 `robotServiceFollowModeJointMove()`，返回后约 1 秒调用 `rootServiceRobotMoveControl(RobotMoveStop)`。

以上数值是本次监督实验的限幅，不是厂家推荐的连续遥操参数。客户端 getter 回读一致只能确认 SDK 客户端配置，不能单独证明控制柜执行限幅。

本次采用串行 SDK 调用，不在 follow 请求等待时并发调用 stop。已知请求可能等待响应，程序没有独立于该等待的可靠软件停止通道；现场实体停止/急停是本次监督实验的独立后备。不能把这个程序用于无人监督或连续遥操。

没有自动上电、握手、清错、切模式、归位、重试或返回起点。关节目标来自本次最新读取，而非旧报告或 RG_READY。

## 实测结果

| 项目 | 本次结果 |
| --- | --- |
| 跟随接口 | 返回 0，调用约 **8.04 ms** |
| 慢停开始 | 跟随返回后约 **1.036 s** |
| 慢停接口 | 返回 0，调用约 **777.24 ms** |
| 慢停前最后一次 J6 反馈 | 相对起点约 **+0.299°** |
| 后续只读核对 J6 | 相对本次起点约 **+0.539°**，未到 +1° 目标 |
| 后续控制柜状态 | RobotStopped=0 |
| 后续设备诊断 | 未报告急停、碰撞或关节错误 |
| 后续 J1–J5 最终变化 | 绝对值均小于约 **0.0004°** |
| 操作者观察 | “肉眼没看清动作，但现在静止” |

SDK 输出慢停返回成功，以及事件 type 1300、`robot controller enter stop state.`。后续独立只读会话采集 12 个有效关节样本，J1–J5 无样本间变化，J6 的样本范围约 0.00063°。该范围是短时反馈波动记录，不在这里定义新的停止判据。

这次证据支持：当前控制柜接受过一次跟随位置目标，J6 实际发生微动，候选慢停使本次运动在未走完目标时结束。仍不能声称多目标覆盖、无积压、反向响应、并发停止、断网停止或正常遥操周期已经验收。

8 ms 是单次跟随请求耗时，不是可持续发送频率保证；777 ms 是这一次 stop 的主机调用耗时，不是由这些离散反馈测出的精确物理停止时间。没有注册带设备采样时间的连续反馈。

## 本次发现并修复的记录问题

慢停返回后的第一次串行“关节 + 状态”查询超过实验设置的 200 ms 观察预算，原程序抛异常退出；该次已收到的原始结果未进入报告。因此首次报告的 `observations_after_stop` 为空，不能用它宣称完整停后观察通过。

程序没有继续发运动目标，也没有重试停止。随后只进行了独立只读核对，取得上述停止状态与关节证据。本次实验结果应标注为“动作与慢停取得实测证据，原停后观察记录不完整”，不是整体无异常通过。

已修复为：始终保留查询原始结果和耗时，再标注超预算/验证错误。运动期间超预算仍终止实验并请求一次停止；已请求停止后的迟到观察保留并标注降级，不因记录问题丢失原始结果，也不自动提高阈值。报告写入异常不得阻止异常路径尝试停止。修复当时未追加动作，后续另行获准进行下面的第二次实验。

新增 3 项小型诊断测试，验证默认预览不加载 SDK、迟到结果保留且原预算继续有效、SDK 错误返回保留。这些不是替代本次真实运动的假设备实验。

完整离线回归 **96 项通过**（37 + 17 + 5 + 7 + 3 + 27），以及原只读绑定隔离/边界检查、脚本语法检查。原生 J6 扩展已编译，并检查未登录时拒绝 snapshot、follow、stop、logout。`git diff --check` 通过。

## 第二次：同范围真机复核，17:06

用户提供了当前机械臂照片，确认法兰附件及悬挂线缆允许 J6 正向 1°微转，不会碰挂或拉紧。程序前置只读核对报告停止、诊断未报告异常，六轴角约为 `(10.342, 15.337, 135.964, 117.080, 86.690, 45.709)°`。只根据控制柜反馈建立目标，不从照片推断精确角度或全空间碰撞余量。

本次复用修复后的同一入口和同一实验限幅，没有修改代码、放宽 200 ms 观察预算或增加目标幅度。开始时间 2026-10-19 17:06:30（北京时间）。

| 项目 | 第二次结果 |
| --- | --- |
| 跟随调用 | 返回 0，约 **6.32 ms** |
| 请求慢停时间 | 跟随返回后约 **1.031 s** |
| 慢停调用 | 返回 0，约 **762.51 ms** |
| 停前观察 | 14 次，均报告运行；最后一次 J6 约 +0.291° |
| 停后观察 | 12 次，均报告停止；另一次最终查询也报告停止 |
| J6 最终变化 | **+0.5502°**，还差约 0.4498°到达本次目标 |
| J6 最终读数 | 约 **46.2591°** |
| 其余关节最终变化 | 最大约 **0.000205°** |
| 停前/停后查询超预算 | 均没有；原始结果完整保留，无异常退出 |
| 操作者确认 | “现在静止，附件和线缆正常” |

停前单次串行观察耗时约 9.1–103.2 ms，停后约 9.0–171.1 ms；主机每次查询后还休眠 50 ms，因此实际采样不是严格 20 Hz。包括最终查询在内，停后 J6 反馈最大差约 0.00168°；这是离散反馈范围，不能宣称严格零速度或测出精确物理停止时刻。

SDK 再次输出进入停止状态的事件。程序返回码为 0，退出登录后没有残留到控制柜的 TCP 连接。本次“单目标 J6 微动 + 串行慢停 + 完整停后观察”的有限实验通过，附件与线缆状态由操作者确认正常。

没有据此开放连续目标、反向动作、SDK 并发、网络中断或 Quest 控制。两次实验都不涉及直接测试这些内容，也没有改变当前位型去其他关节归位。

## 文件和入口

原始文件实际位于 `/data/VR_teleoperation_runtime`：

- `aubo-j6-first-real-20261019.json`、`.log`：首次运动报告及包括 SDK 原始输出的终端日志；保留原记录，未覆写为修复后的结果。
- `aubo-j6-postcheck-20261019.json`、`.log`：之后的独立只读核对及 12 个关节样本。
- `aubo-offline-after-j6-20261019.log`：修复后的离线回归。
- `aubo-j6-second-precheck-20261019.json`、`.log`：第二次实验前只读检查。
- `aubo-j6-second-real-20261019.json`、`.log`：第二次同范围运动和完整停前/停后记录。
- `aubo-j6-second-summary-20261019.json`：第二次结果摘要、反馈范围及原报告 SHA256。
- `build-j6-trial/`、`j6-trial-build.json`：单独的原生扩展及库/模块哈希清单。

代码集中于 `teleop/aubo/j6_trial.py` 和 `teleop/aubo/native/j6_trial.cpp`。没有改作者 IK 或仿真基线。`J6Trial` 只提供固定 J6 单次实验，不接受任意关节目标；每个客户端最多一次跟随尝试和一次停止，停止后不能再发目标。后续另加的 `J6StreamTrial` 是有独立范围和次数限制的连续实验，见下面链接。只读扩展和静止停止扩展仍保持原接口。

默认命令只打印实验预览，不加载 SDK、不连接、不运动：

```bash
cd /home/lcw/VR_teleoperation
bash scripts/aubo_j6_trial.sh
```

构建命令也不连接设备：

```bash
bash scripts/build_aubo_j6_trial.sh
```

仅在现场监督并明确要再做同一实验时，使用运动入口；每次必须使用新的报告名，程序不自动覆盖：

```bash
bash scripts/aubo_j6_trial.sh --execute --operator-ready \
  --host 192.168.1.5 --port 8899 --user aubo \
  --output /data/VR_teleoperation_runtime/<新的报告名>.json
```

该命令会实际移动 J6，不是只读命令。其他测试关节、幅度或连续目标需单独设计，不能通过取消本次保护直接扩大范围。
