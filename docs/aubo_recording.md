# AUBO 无相机录制与 LeRobot v3.0 导出

2026-10-29 第一版：串行 Follow 控制保持，新增显式开启的后台录制、手柄事件和离线导出。未启动真机验收；本文的自动验证均为明确标注的隔离合成数据或模拟 SDK。

## 数据格式与含义

实时保存 `aubo_state_action_v1` 原始记录，退出采集会话后使用本机 `/data/lerobot/.venv/bin/python` 的 LeRobot 0.6.2 写入器生成标准 v3.0 数据。遥操环境不导入 Torch、Arrow 或 LeRobot，不增加 SDK 查询或连接。默认记录状态快照 25 Hz，独立于 Follow 的请求频率；不补造超时周期。

- `observation.state`：J1–J6 实测关节角，float32[6]，弧度，源为现有反馈缓存。
- `action`：SDK 返回成功的 J1–J6 绝对目标，float32[6]，弧度。不是未发送的 IK 候选，不是下一帧实测角，也不证明实体已经执行到位。
- `source.*`：原始 episode 编号、快照序号、主机快照时间、反馈接收时间、命令开始与返回时间；时间为 float64 秒，保留原始时钟精度。
- `observation.state_age_s`、`action.age_s`：使用的反馈与已知命令的年龄。
- LeRobot 自带的 `timestamp` 是导出片段内的均匀采样时间；不冒充控制柜采样时间。Quest 的源时间单独保留在原始记录中。
- 没有相机、图像、夹爪实测字段；不生成空白图像或虚构夹爪数据。不上传 Hub。

实时目录：

```text
/data/VR_teleoperation_runtime/recordings/aubo/<时间>-<随机后缀>/
  manifest.json                 # 模式、单位、任务、倍率、映射与时间来源
  streams.jsonl                 # XR、SDK 请求/结果、状态快照、候选与操作事件
  episodes/episode_000000.json   # 分段边界、保存/无效/中断标记及计数
  session_status.json           # 关闭结果、错误和丢失计数
```

所有写盘、序列化和 fsync 在后台线程执行。生产者只向有限队列提交记录。队列溢出或磁盘错误会显示录制失败，并请求软件停止、锁定操作；不会丢记录后继续宣称录制成功。只有完成流文件 flush/fsync 和原子写入分段摘要后，页面才显示已保存。目录必须是 `/data` 下的新目录，不覆盖旧数据。

## 启动

```bash
cd /home/lcw/VR_teleoperation
bash scripts/aubo_quest_follow.sh \
  --execute-six-axis --command-mode follow --follow-hz 25 \
  --waypoint-feedback --serial-state-query \
  --host 192.168.1.5 --port 8899 --user aubo \
  --rotation world --duration 1800 \
  --record --record-fps 25 \
  --task "通用机械臂遥操轨迹采集"
```

`--task` 应替换为这次实际操作的描述。可以给 `--record /data/.../新目录` 指定位置。程序启动后是待录制；向左推左手摇杆才开始一段。不传 `--record` 仍关闭录制。SDK 密码只在终端输入。

使用 AUBO Quest 页面进入头显透视后，视野下缘会出现头部跟随的状态卡，每秒更新约两次。状态卡显示当前第几段、录制时长、上一段写盘确认结果、保存中状态或录制错误；HTTP 状态接口超过约 2.5 秒未更新时显示“录制状态连接中断”，并把旧状态标作最后确认信息。只有实际启用 `--record` 的会话会显示采集状态；普通没有录制的会话显示“录制未启用”。状态卡文字来自 `/aubo/status`，新建或重新启动遥操会话后加载更新的网页与客户端代码。最终字体大小、视野位置及透视可见性需在 Quest 头显现场确认。

真机入口目前使用 1.0 秒有效 Quest 输入超时；收到右 Grip 松开事件时立即撤销发送许可、请求停止，不等超时。此设置写入 `manifest.json` 的 `metadata.input_timeout_s`；主机收到松开事件到实际停稳仍有 SDK 调用和减速耗时。输入暂缺时可能继续追随最后目标；旧姿态的相对源延迟检查仍为 200 ms，状态／反馈／SDK 其他保护独立保留。

## 操作

| 输入 | 功能 |
| --- | --- |
| 右 Grip | 原有离合；松开或输入超时给当前段写入 `pause` 标签并挂起采样；重新按下且成功接合后继续同一段 |
| 左 Grip | 未分配；不触发遥操或录制暂停 |
| 左 Y 按住 | 直接请求返回已保存原位；无需右 Grip。松开 Y 或左手输入丢失会撤销回位，需松开后重新按住 Y 才能再次启动 |
| 右 A 按住 | 原有精细映射，默认倍率为普通模式的 0.5 |
| 右 B | 未分配；不暂停遥操或录制 |
| 右摇杆按下 | 写事件标记；不归位 |
| 左摇杆向左推 | Restart loop：作废当前采摘循环，停稳并保存原始数据后开始新循环 |
| 左摇杆向右推 | Exit the loop：结束并保存当前采摘循环，不结束整个录制会话 |
| 左摇杆向上推 | Exit the record：结束并保存整个 Episode 录制会话 |
| 状态页“软件复位（不回位）” | 确认停稳、反馈新鲜后清除旧目标及映射锚点，在当前位置重新对齐；不结束当前段 |
| 其他状态页按钮 | 暂停、开始/保存、无效、标记、准备运动回原位和停止结束会话 |

左摇杆三个方向是边沿触发，必须先回中才能再次触发。向左重启时，当前段标记为 `invalid` 并保留原始流，保存确认后自动开始下一段；向右退出循环只保存当前段，不自动开始新段；向上退出记录会保存当前段并锁定整个采集会话。网页手动暂停、硬件故障锁和录制错误独立保留。

普通右手遥操不要求左手出现；左 Y 回位时则必须持续收到有效的左手 Y 按住状态。连接、参考空间重置或手柄重新出现时，已经推住的摇杆不算新的动作，需先回中；一直按住的 Y 也不会自动启动回位，需松开再按。管理事件在接收端独立缓存，不受姿态 latest-only 覆盖；三个方向事件在接收端即撤销发送许可，不等待下一次 IK。

Grip 松开和输入超时都会给当前段写入 `pause` 标签并挂起采样；暂停期间不写新的 XR、SDK 或状态采样。重新按下 Grip 后，必须等离合实际恢复为 active 并重新接合，才写入 `resume` 标签并继续同一个 `episode_id`。导出会在暂停和恢复处切开有效片段，不会把两侧动作无痕拼接。

运动回位由左手 Y 按住直接发起，无需先点击网页，也无需按右 Grip。程序先撤销原有运动许可，等待确认停稳及新鲜关节反馈，再在 Y 持续按住时生成回位目标。松开 Y 或左手数据缺失会在接收端立即撤销发送许可；有效按住状态超过 200 ms 未刷新时也会取消回位。断连、参考空间变化或重连后持续按住 Y 不会自动重启，需松开后重新按住 Y。网页“准备运动回原位”仍可预备回位，但运动同样由左 Y 发起。回位过程中右 Grip 的松开不取消回位；右 Grip 继续负责普通遥操离合。实体停稳仍需 SDK 调用和减速时间。到达保存姿态并确认停稳后不重复启动；松开 Y，再松开／按下右 Grip 可重新接合遥操。

回位仅在六轴 `follow` 模式且成功加载有效原位文件时可用；网页暂停或切段期间需先解除暂停或等待切段完成。当前每轴回位目标速度上限为 **20°/s**，目标加速度上限为 **6°/s²**，到位关节误差容差为 **0.15°**。这些参数约束主机生成的回位目标，实际速度取决于控制柜执行和反馈；普通手柄遥操的 IK 参数、SDK 运动参数与发送频率按各自现有配置运行。回位请求会挂起当前录制段的普通采样并保留回位生命周期事件，不主动结束当前段；重新使用右 Grip 成功接合遥操后续录同一段。回位目标在 worker 中仍标识为 `control_source=home_return`，不作为训练动作导出。

软件复位由网页“软件复位（不回位）”触发，没有手柄按键绑定。它会先请求停止；控制柜状态为停止、关节反馈新鲜后，控制线程清除旧目标与映射锚点，页面显示“软件复位完成”。它不结束或作废当前段，不读取原位文件、不清除标定、不发送回位命令、不清硬件故障；完成后仍需新的 Grip 松开／按下，下一次接合从实测位置重新对齐。硬件故障、停止结果未知或会话结束会取消待执行复位和自动重开，反馈过期时不能宣称复位完成。右摇杆仍只添加标记。独立 MuJoCo 仿真入口仍使用右摇杆按下归位，详见[仿真操作约定](mujoco_teleop.md#操作约定)。

状态页为 `https://127.0.0.1:8443/aubo`（USB 模式使用 HTTP），JSON 为 `/aubo/status`。显示当前模式、暂停锁、录制状态、当前段、最近保存结果、回位状态及错误；录制挂起时显示“录制已暂停，等待 Grip 重新接合”。JSON 还显示 `recording_paused`、`collection.pause_reason`、`episode_transition`、`software_reset_pending` 和 `home_return`。`home_return` 包含是否可用、原位文件、状态、目标速度/加速度上限及最大关节误差。网页“请求已提交”只表示入队，以随后的操作提示和状态为结果。`POST /aubo/operator/{command}` 接受 `pause`、`toggle_episode`（开始／仅保存）、`restart_loop`、`exit_loop`、`exit_record`、`return_home`（网页）、`software_reset`（仅网页）、`invalidate`、`mark`、`finish_session`。所有命令都不会清除硬件故障。

右 Trigger 当前仍未接实体夹爪。软件暂停依赖原有通信与停止链路，不替代实体急停。普通 Ctrl+C、窗口关闭或超时退出时，仍在进行且未主动保存的段标记为 interrupted；已保存的段保留。

## 导出

关闭采集会话后运行（替换原始目录及新的输出目录）：

```bash
bash scripts/aubo_export_lerobot.sh \
  --input /data/VR_teleoperation_runtime/recordings/aubo/实际会话目录 \
  --output /data/VR_teleoperation_runtime/datasets/aubo_state_action_001 \
  --repo-id local/aubo_state_action_001
```

导出只使用已正常保存且未出现异常停止的原始段。缺少关闭摘要、记录序号不连续、计数不符、写盘错误或队列溢出的会话拒绝导出。无效、中断和异常段保留原文件，在 `export_report.json` 列出跳过编号。

按固定帧率做因果采样：只取该时刻已经记录的最新反馈及 SDK 成功接收的目标，不偷用未来数据，不插值。反馈需在 200 ms 内，命令需在 650 ms 内；这只是导出质量条件，不改动真机保护。正常松开 Grip、暂停、停止或数据空档没有有效动作时，导出切分连续有效片段，不把断点两侧无痕拼接。每个有效片段至少两帧；`export_report.json` 保存 LeRobot episode 到原始 episode 及真实时间范围的映射。原始完整 episode 不受导出切分影响。

无相机数据可检查遥操轨迹和录制流程，不能补出未来才接入的相机画面。当前 action 表达为绝对关节位置；后续换为增量、末端位姿等训练表达时，应从原始记录派生并保存转换说明。
