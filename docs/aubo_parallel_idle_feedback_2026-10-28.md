# 双连接第三次现场失败：空闲反馈过期被误判为永久故障

## 现场证据

用户第三次报告“动了一次就无法控制”。读取本地状态保留的快照为 `/data/VR_teleoperation_runtime/aubo-parallel-third-20261028-202016.json`。排查未清锁、未登录新增设备连接、未自动重启真机。原 120 秒会话已自然结束。

本轮成功提交 169 次 Follow，最后一次返回 0。首次停止原因为正常 `grip_released`；慢停耗时 979.437 ms，返回 0。停稳确认于主机单调时间 8923.884145044 成功，`stop_confirmed=true`、`stop_result_unknown=false`。因此上一轮停止确认等待修正确实覆盖了本次停止过程。

永久故障发生在确认后 3.944 秒，`first_fatal.prior_state=idle`，原因为 `RuntimeError: Parallel state/joint feedback reception expired`。当时：

| 数据 | 最近接收时间 | 故障时接收年龄 |
| --- | --- | --- |
| 关节推送 | 8927.627423749 | 201.102 ms |
| B 运行状态 | 8927.783539728 | 44.987 ms |

B 本次查询耗时 13.736 ms，返回码 0、状态 0，线程存活且无错误。后续快照显示推送已恢复至约 23.59 ms 年龄，但 `_run()` 已把 `_observe()` 的过期异常锁为 fatal，后续不能接合。旧 `feedback_age_s` 反映最近处理快照的年龄，故障时仅 3.696 ms，不能代替原始关节/状态接收年龄。

目前证据能确定的是“空闲期关节推送间隔超过 200 ms 导致永久锁定”。间隔来自控制柜推送行为、SDK 回调调度还是网络，尚未确定，不能把这份证据解释为 B 查询断连或双连接争抢。

## 修正规则

并行模式中，原生返回的有效但过期观测统一产生 `ObservationPending`，保留真实原始记录和接收时间。处理按阶段区分：

- 空闲、尚无运动许可：标记 `feedback_ready=false`，撤销原生许可、清空目标及接合屏障，等待新反馈；单纯过期不再永久锁定。
- 等待接合：过期期间的意图被丢弃。运行层也清除旧输入/作者锚点，显示 `waiting_for_feedback`；反馈恢复不自动运行，须有新鲜释放/按下建立新锚点。
- 已允许运动：仍执行原故障停止流程，200 ms 原生 arm/send 检查没有放宽。
- 停止确认：继续沿用原 2 秒截止时间等待，过期样本不参与静止窗口；真正失败及超时仍为故障/停止未知。
- 空闲时即使关节过期，新鲜 B 状态若显示非停止，仍触发 `unexpected_motion_while_idle` 并请求停止。不能因等待关节而忽略独立状态通道的异常运动。

真实查询失败、未知状态、缓存代次失效和 SDK 超时仍按既有规则处理。后台线程无自动恢复运动许可的能力。

等待期间保留关节缓存原始时间戳；不以主机处理时刻覆盖它。否则刚恢复、但接收于那次覆盖之前的合法推送会被误判为乱序。目标和原生许可门控保证旧缓存不能用于恢复运动。

状态增加 `last_observation_attempt`（含原始快照、检查时间、关节/状态各自接收年龄），首个停止/故障事件增加 `reception_age_s`，可直接区分状态过期和关节过期。

## 离线复现与验证

假 SDK 增加暂停/恢复关节推送控制，直接编译生产绑定，无供应商连接或设备运动。新增用例先在修正前重现与现场一致的 idle fatal，再验证：

1. 连续三轮正常接合、发送、松开停稳、空闲推送中断超过 200 ms、恢复及再次接合，无永久故障。
2. 中断期间不 arm、不发送、不缓存恢复后自动执行的意图。
3. 空闲 B 状态过期可等待；关节过期但新鲜状态显示运动仍触发停止。
4. 运动中关节过期仍撤销并停止，反馈恢复不自动解锁。
5. 包含实际 `J6QuestRuntime`、作者核心及生产绑定的完整链路：反馈恢复后持续按住无效，新释放后一次按下可重新接合。

完整离线检查通过：274 项 Python 单元测试、15 项生产绑定/假 SDK 集成，共 289 项；另有供应商绑定未连接拒绝、原生 profile/透传生命周期、默认入口及 Shell 检查。构建和日志均存于 `/data/VR_teleoperation_runtime`：

- `aubo-idle-gap-build-20261028.log`
- `aubo-idle-gap-reproduction-20261028.log`：修正前预期失败的复现证据。
- `aubo-idle-gap-focused-20261028.log`
- `aubo-idle-gap-check-20261028.log`

以上验证证明本次软件故障链被离线覆盖。尚未进行修正后的真机验收，也没有证明关节推送间隔已被消除或发送频率已提高。
