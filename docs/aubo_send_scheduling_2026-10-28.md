## 本次修改

`teleop/aubo/follow.py` 保持 SDK 单实例、单 owner 串行调用：

1. 持续六轴跟随且启用 waypoint push 时，同步状态查询按 100 ms 独立节拍调度，发送仍按 50 ms 调度。查询节拍从原状态实际接收时刻计算，不伪造新时间。
2. 启动与重新接合前，即使有近期 idle 缓存，也先获取新的状态/关节快照。idle、非推送路径和旧 J6 的常规查询节拍保持 50 ms。
3. 等待时间考虑下一发送截止时刻，避免原固定最多 5 ms 等待跨过已知的发送时点；依旧不补发历史点。
4. 查询返回后重新读取最新候选。查询期间释放 Grip 会撤销许可，不能继续发送。
5. 状态显示和启动输出报告查询策略及实际采用的查询周期。

100 ms 是本项目本轮调度参数，不是厂家推荐频率。关节/状态反馈有效期仍为 200 ms，原生层继续检查真实接收年龄；查询失败、过期、返回异常不会被新策略掩盖。查询仍可能阻塞某一条目标，不声称消除了同步 SDK 的长尾。SDK 参数、关节范围、无3°误差截止、作者 IK/方向映射、正常/故障 Grip 规则、慢停及停止预算均不变。没有引入 SDK 并发调用或额外位置整形。

新增 `teleop/aubo/analyze_follow.py`：离线读取 JSONL，按接合段统计实际发送频率、跟随/状态查询耗时、候选年龄和停止时序；默认只输出终端，显式输出文件只允许 `/data` 且不覆盖旧文件。不加载厂家 SDK、不连接机械臂。

完整离线回归236项通过（原222项，加9项调度回归、5项诊断分析测试），原生绑定边界/profile检查、默认入口和Shell检查通过。日志 `/data/VR_teleoperation_runtime/aubo-scheduling-fullcheck-20261028.log`。覆盖查询与发送独立节拍、接合前新查询、慢查询不插入首个到期发送、查询期间候选更新/Grip释放、查询失败/过期禁止发送、停止优先以及不补发。原生源码和SDK未修改，无需重新构建绑定；这些检查不等于实体跟随体验验收。
