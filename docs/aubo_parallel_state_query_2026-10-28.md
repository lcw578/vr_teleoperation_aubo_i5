## 实现分工

- A：`J6Follower` 保留运动、慢停、初始化检查和关节角回调。运动及停止 SDK 调用仍串行。
- B：`RobotStateObserver` 使用独立 `ServiceInterface` 和连接，查询运行状态；2026-10-29 增加 B 关节推送，与 A 共用有界反馈缓存。没有运动、上电、参数写入或模式切换 API。
- `StateQueryWorker` 是 B 查询的唯一线程所有者。2026-10-29 将周期修正为查询开始到下次开始：运动中 100 ms，idle/停止阶段 50 ms；调用超过周期时，返回后开始下一次，始终只有一个在途查询，不补发积压请求。此前“返回后再等一个周期”的实现会把调用时间叠加到更新间隔。实际查询频率仍受调用耗时影响。
- B 在查询返回后短暂持有缓存锁发布结果；网络请求期间不持有缓存锁，也不持有 A 的 I/O 锁。A 的 `snapshot()` 在此模式下只读取状态缓存和关节推送，不向控制柜查询。
- A 的 arm 和 send 前检查均重新读取最新状态缓存与关节推送，不再依赖周期 snapshot 才刷新原生关节测量值。

状态缓存记录查询开始/接收时间、返回码、状态、连接代次及序号。缓存失效递增代次，旧代次在途结果不能恢复缓存。不提供自动重连和串行降级。状态与关节反馈仍分别按真实主机接收时间检查 200 ms 时效，普通 SDK 调用预算仍为 500 ms，不把读缓存的当前时刻写成状态接收时刻。

查询失败、未知运行状态或 active 时状态过期，撤销本地运动许可，按原故障流程处理；后台查询没有恢复运动许可的能力。SDK 定义的暂停/恢复（2/3）可以作为有效观测继续查询，但不能授权运动；停止确认期间继续等待状态 0 和新鲜静止证据。真正观测失效时无法取得停稳观测，停止确认必须保持失败/未知，不能因停止 API 返回成功就伪报停稳。

## 接合、停止与退出时序

首次/再次接合：收到新接合意图后，请求 B 刷新；发送线程继续循环但不 arm，直到状态缓存中的查询开始时间晚于该次意图屏障，并满足当前停止状态和反馈时效检查。正常 Grip 恢复规则保持，离线验证包含正常释放确认后的首次接合。

Grip 释放时立即撤销许可、丢弃候选，A 在自身在途调用返回后执行慢停；B 的查询不占用 A 的锁。慢停返回后设确认屏障，要求用于确认的状态查询在屏障之后开始，关节反馈也在屏障之后收到。静止窗口使用真实关节推送时间戳，至少跨越 100 ms，不能重复读取同一帧来累计静止时长。原有慢停完成与反馈确认预算均保持 2 秒。

A 的普通调用和 B 的查询分别记录在途操作，watchdog 分别检查。正常退出先等待运动线程完成停止/确认，再停止并 join B，两个工作线程都退出后才 logout。A 先 logout，随后 B logout，此时已经没有运动或查询线程使用连接。

任一线程在途卡住，禁止对两套连接并发 logout/销毁。异常退出将 SDK 原生分配保留至进程退出，并保留 A 的回调缓冲区，避免仍运行的 SDK 回调访问已释放对象。该处理不提供独立物理停止能力；A 自己在途的 SDK 调用仍不能被本地撤销打断。

## 诊断与离线验证

状态中新增 `state_query_policy=independent_sdk_connection`、`sdk_connections=2`、`motion_sdk_calls_serial=true`，以及独立 `state_observer` 在途/最近查询/错误字段。详细诊断记录每次真实 B 查询的 `state_query_returned` 事件；分析工具使用这些事件计数，避免把运动循环重复读取缓存误算成多次查询。2026-10-29 流式诊断使用 4096 条内存历史和 8192 条待写队列，后台持续写文件，队列覆盖会显式记录缺失数；不再额外保留 100000 条复杂对象。原生反馈读取支持按序号增量返回，避免每个 5 ms 周期反复转换全部 256 帧。详见[双路反馈测试及调度修正](aubo_redundant_feedback_trial_2026-10-29.md)。

构建假 SDK 时直接编译生产 `follow.cpp`，只替换 SDK 头文件，不链接供应商库、不打开设备 socket。原生集成验证覆盖：

1. B 请求卡住，A 的缓存读取、发送与停止仍可完成，A 不增加运行状态查询。
2. 新关节推送直接进入原生发送前检查，不额外查询。
3. 查询失败、暂停状态、200 ms 状态过期以及本地失效都拒绝运动提交。
4. 在途旧查询的迟到返回不能覆盖缓存失效。
5. watchdog 在 B 阻塞和状态过期时撤销许可，迟到返回不恢复许可。
6. 完整 worker 的发送、Grip 慢停、停止后的新查询确认、首次重新接合及线程退出。
7. CLI 创建两套连接、后台就绪及正常关闭，未发送运动目标；socket 和页面服务均替换为离线 mock。

Python 单元检查另外覆盖 B 初始查询失败、错误时间戳、线程在途状态的非阻塞读取、退出遇到卡住查询时拒绝 logout，以及 CLI 参数边界。完整既有回归也覆盖 Grip 恢复、方向/IK、旧 J6 和透传生命周期。

最终构建与完整离线检查通过：273 项 Python 单元测试、8 项生产绑定/假 SDK 集成测试，共 281 项；另有供应商绑定的未连接拒绝检查、原生 profile/透传生命周期检查以及默认入口与 Shell 检查。日志保存在 `/data/VR_teleoperation_runtime/aubo-parallel-state-build-20261028.log`、`aubo-parallel-state-check-20261028.log`。时序调整的定向日志为 `aubo-parallel-state-final-focused.log`、`aubo-parallel-state-final-native.log`。
