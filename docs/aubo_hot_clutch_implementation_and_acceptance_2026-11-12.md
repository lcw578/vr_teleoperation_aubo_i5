## 最终实现

- 冷接合：IDLE → arming/Enter → PRIMING → ACTIVE。Python 与 native PRIMING 总上限均为 2.5s；固定锚点、400ms 单次/年龄边界、至少 12 帧、连续 5 帧 ≤25ms、State Age ≤100ms、Joint Age ≤60ms、关节偏差 ≤0.1°的门槛保留。
- 正常松 Grip：ACTIVE → BRAKING → HOLDING；保留 native 透传许可，不执行 Leave。上游目标停止消费；BRAKING 从当前 q/v/a 规划自由终点、零末速度/加速度的五次 Bezier 制动曲线。通过位置/速度/加速度/jerk 的 Bernstein 控制点约束认证整段，搜索首个可行时间区间后细化。**这是所选曲线族/搜索范围内的保守短时制动，并非全局最短时间控制证明**。不可行即故障停止，不能沿用旧运动目标冒充制动。
- BRAKING 参考/反馈偏差上限 3°；参考静止后，反馈必须距 q_hold ≤0.1°，且连续至少 100ms 位姿变化 ≤0.02°，才转 HOLDING。BRAKING 最多 3s，逾时故障停止。
- HOLDING 重复固定 q_hold；继续 200ms 状态/关节年龄保护，距保持点 >0.1°锁死。热重接合要求连续 5 次成功调用 ≤25ms、最近发送起点距当前 ≤50ms、State Age ≤100ms、Joint Age ≤60ms，以及仍满足最近 100ms 静止检查。只有输入 owner 确认最新有效且按住的手柄位姿已重新锚定后，才允许 resume_clutch。普通 offer 无法使 BRAKING/HOLDING 恢复运动。
- 冷/热切入 ACTIVE 都强制第一条实际发送为精确锚点，q/v/a 重置为 q_anchor 或 q_hold / 0 / 0。即使新 IK 目标先到，也不能覆盖这一帧。
- HOLDING 空闲 20s、输入断连、会话退出或保护触发，仍走 Leave → 慢停 → 新鲜反馈停稳确认。20s 是持续有效 XR 输入下的热保持上限；不再收到输入仍使用原输入超时退出。
- Leave 完成后 Python/native 均要求最小 0.5s 冷却。单纯冷 PRIMING 总时限到达/松 Grip 不再永久锁死，但必须完成退出/慢停/停稳确认，经过原运行时的松手恢复门。停止期间也核对锚点偏差；位置偏差、400ms 边界/SDK 异常或停止确认失败不降级为可恢复超时。
- 运动上限保持 10°/s、30°/s²、300°/s³；实际 dt 推进上限 50ms。以上是主机参考曲线约束，不宣称实测电机导数已被验证。

## 验证和实际顺序

所有实机测试由有限时长 harness 调用生产 J6FollowWorker 和 A/B/C；不接自由 VR。新建文件与日志位于本机 `/data/VR_teleoperation_runtime/hot-clutch-20261112/`，车载同名目录位于既有 `/home/xc/code/lcw/VR_teleoperation_runtime/` 下。记录各轮源码/native 哈希，保留原始报告，不把不同源码轮次合并成一轮通过。

- PRIMING 18 次，最大调用 253.192ms；ACTIVE 静止 5.000s，450 次发送。
- A P50/P95/Max：6.134 / 22.313 / 106.020ms。

### 第一轮 5 次离合连通性：通过，但不足以作为最终验收

- 单次冷入模；PRIMING 0.535s、13 帧、最大 262.407ms。
- 后续 ACTIVE/BRAKING/HOLDING 连续窗口 13.033s；5 次 release/resume，只有 1 次 Enter，结束才发生 1 次 Leave/慢停。
- ACTIVE 892 次调用：P50/P95/Max = 5.523 / 20.157 / 51.631ms。
- BRAKING 51 次：9.579 / 18.198 / 22.537ms。
- HOLDING 230 次：9.683 / 19.858 / 118.211ms。
- 全窗口 State Age / Joint Age 保守上界 = 152.789 / 65.357ms。
- 5 次从 release 到 HOLDING：144.721 / 146.704 / 166.229 / 136.785 / 136.938ms。
- release 到 resume（包含程序要求的 0.75s 保持和准入等待）：933.377 / 750.968 / 750.506 / 867.223 / 750.472ms。
- 重接合首个实际目标增量最大 0.000023°，非常小但非精确零。因此之后增加强制首帧锚点规则。
- **该轮使用固定 ±1°目标、每轮 1.5s。日志显示松手时参考速度均为 0，故只证明热离合连通性/保持，不能证明运动中制动实机性能。** 随后将计划改成持续变化的 ±0.8°正弦目标，要求在非零参考速度时松手。
- 最终返回初始点误差约 0.004413°，停稳确认通过。

### 精确首帧版本复测：静止 ACTIVE 中失败，后续运动取消

- `stage-A-final/report.json` 保留本次精确源码哈希。
- PRIMING 0.609s 收敛，最大调用 183.779ms。
- ACTIVE 约 3.547s 后，触发 `state_reception_expired`。B 接收年龄约 201.285ms；当时 B 请求仍在等待。
- 同时 A 固定姿态发送总耗时 256.710ms，返回记录 `revoked_during_call=true`。这次没有 VR/IK 运动增量，也没有连续 Leave/Enter。
- Watchdog 在 A 阻塞时撤销本地许可；SDK 调用不能被中途取消，返回后串行退出/慢停。Leave 31.372ms、慢停 61.056ms，rc 均为 0；从保护触发到停稳确认约 470.367ms。
- 最终 `stop_confirmed=true`、`stop_result_unknown=false`；验收 harness 将异常锁为 fatal，不再自动重试。实际关节相对初始点变化最大约 0.000628°。
- 此窗口 NIC errors/drops/collisions 均未增加。**没有新 PCAP，不能仅凭这些计数定位 SDK/TCP/柜端业务等待，更不能认定由半双工造成。**
- 同一命令链要求静止 A 通过后才能执行 CLUTCH。A 失败后改进的运动中松手测试未运行，没有用早期成功记录替代。

这说明“第三轮失败必然只由频繁模式切换导致”仍只是待验证假设；当前已有单次冷入模后 ACTIVE 静止出现共同长等待的反例。热离合减少模式切换，但不能保证解决稳态长尾。
