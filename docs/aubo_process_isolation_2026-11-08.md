# AUBO 状态 SDK 进程隔离：实施与真机结果

2026-11-08。用户授权实施“发送和状态查询分进程”，保持现有保护并继续有限实机验收。**代码已完成、本地和车载均已构建部署，但短时保持验收仍未通过，尚不能恢复自由 VR 遥操。**

## 最终实现

- 控制进程只构造一个运动 SDK 对象，持有连接 A。关节反馈只订阅 A；进入、发送、退出、停止仍由原串行 owner 执行。
- `ProcessStateObserver` 用 `subprocess.Popen([sys.executable, '-m', ...])` 启动全新解释器。子进程独立加载 SDK，只构造 `RobotStateObserver`，只接受 login/query/logout 三类请求，不提供运动、启动或清故障接口。不会 fork 后沿用父进程 SDK 对象。
- 原计划提到共享内存；最终采用**私有双向管道 + 控制进程内原生缓存**。父进程原有状态线程负责 IPC 等待和发布；发送线程不读管道、不等待查询，只读 `RobotStateCache`。这样无需增加跨进程共享锁和共享内存生命周期，仍隔离了两份 SDK 的全局变量和互斥资源。
- 密码通过私有管道传给子进程，不出现在命令行或状态报告。启动只传入该管道描述符，其他 SDK socket 不继承。
- 缓存保留子进程 SDK 查询的起止时间、返回码及 generation。IPC 收到数据的时间另记，绝不替换真实接收时间。过期、失效或来自旧 generation 的结果不得重新授权运动。
- 接收新鲜度 200ms、SDK 预算 500ms、停止后新鲜状态及稳定关节判据保持。B 子进程或 IPC 失效会使缓存失效，不自动重连或恢复运动。只有只读子进程允许在无法正常退出时被终止，不对运动进程实施同类清理。
- 停止确认完成、原状态线程退出后，才执行 B 登出与子进程回收。旧的同进程 `RobotStateObserver` 接口保留供原测试和兼容路径使用；Quest 并行状态入口和透传启动器要求新的进程缓存能力。

涉及文件：`teleop/aubo/process_state.py`、`native/follow.cpp`、`follow.py`、`quest_follow.py`、`scripts/aubo_passthrough.sh`、`scripts/build_aubo_follow.sh`。未改 VR 映射、IK、alpha、路由、调度或机器人设置；未增加运动整形，此任务仅处理状态 SDK 隔离。
