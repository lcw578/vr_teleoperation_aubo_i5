当前结论：PC 与控制柜通信、只读查询、模型数学对照、J6 独立跟随与运动中改目标已取得真机证据；Quest 已产生实际发送给控制柜的 J6 目标。完整六轴遥操尚未开放，最新慢停时序修正仅完成构建和离线回归，尚待现场复测。当前运动会话已关闭，最后一次只读核对与现场观察均确认静止。

本次整理只写文档，没有连接 SDK、发送停止/运动、修改运动配置或启动录制。

## 2. 控制方式：现在到底用什么

```text
Quest 右手柄
  → 作者 WebXR 腕部校准与位姿/按键输入
  → 电脑 HTTPS / WebSocket Relay
  → 输入验证、最新帧缓存、Grip/故障事件保留
  → 原作者滤波、离合、目标管理、3+3 解耦 IK
  → 六关节候选位置
  → 当前联调只取 J6，J1–J5 固定为启动实测角
  → 最新目标槽、限幅/限步长/时效检查
  → 厂家 robotServiceFollowModeJointMove(q)
  → AUBO 控制柜执行运动

控制柜关节/状态查询
  → 反馈缓存
  → 实际状态锚定、故障判定、模型显示和停止确认

Grip 释放/输入故障
  → 立即撤销主机发送许可并清空候选
  → 串行 SDK owner 请求慢停
  → 反馈确认
  → 等待新的 Grip 释放/按下
```

主机给的是关节位置目标，不要求通过速度接口发送速度。SDK 的速度/加速度配置属于运动参数，不等于速度控制模式；我们没有重新实现底层电机伺服器，也没有验证其内部电流环或力矩环实现。

FollowMode 调用不等待关节到位，但仍同步等待请求响应。因此不能称为完全不会阻塞。实测说明运动中能采用新位置目标；不能由此保证任意频率下所有目标立即覆盖、永不积压。

MuJoCo 在真机入口中负责模型 FK、作者 IK 和桌面显示，不把仿真动力学作为真实关节反馈。实体色模型跟随实测关节，青色模型显示候选；当前 J6 入口中的青色目标经过 J6 投影，实际限步长后送入 SDK 的目标另行记录。

## 3. 通信、只读查询和 SDK 兼容处理

### 3.1 修复 SDK 加载冲突

首次加载出现段错误或登录内部异常。定位到 SDK 自带 tiny-regex 的 `re_match` 与 libc 同名但 ABI 不同，SDK 内部调用错误绑定到了 libc。

正式加载器改为核对 SDK SHA256，以绝对路径及 `RTLD_NOW | RTLD_LOCAL | RTLD_DEEPBIND` 隔离装载，再核对实际映射库和查询白名单。没有修改厂家 SDK 二进制或 Python 全局加载标志；发现此前已被其他路径加载时拒绝继续，避免在错误绑定上运行。

### 3.2 完成正式只读检查

修复后，登录、17 项默认查询、1 项 SDK 本地 FK 和退出均成功。取得版本、设备类型、状态、诊断、关节反馈与范围等信息。该次正常网络 Get 约 5.3–15.4 ms，不作为实时保证。

`GetJointPositionLimit` 在本设备返回 `10007`，等待约 5.000143 秒；它已从默认探测中排除，保留显式诊断能力和排除原因。这个约 5 秒是失败查询的超时，不能描述成正常跟随运动需要 5 秒。

区分了结果来源：`GetToolKinematicsParam` 读取 SDK 客户端运动配置，不能当作示教器 TCP 查询；SDK FK 是本地计算，不混入控制柜响应耗时。

控制柜报告范围约 ±174.900°，示教器页面显示 ±175°，尚未确定差异含义；没有擅自放宽控制柜保护。SDK 初始化警告 `Get movep joint range failed` 和 `Ikfunc::SetDhParaLen unkown robottype[0]` 保留，未宣称根因已解决。

详细记录：[只读修复与实测](aubo_readonly_fix_2026-10-19.md)。

## 4. 示教器、法兰与模型对照

人工核对了示教器 `Base / Flange_center` 页面与 SDK 的关节、位置和姿态。静态读数对应，为当前法兰定义提供证据；不等于已逐轴验证正方向、零位或全工作区精度。

模型 `wrist3_Link` 与 SDK FK 之间的数学关系为：

```text
T_sdk_base_flange = TransZ(-0.0235 m) × T_model_base_wrist3
```

38 组本地数学计算对照中，换算后最大位置差约 `2.72e-16 m`、方向差约 `5.96e-8 rad`。这些关节配置没有作为运动目标发给实体；结果证明数学模型一致性，不能当作物理标定精度。23.5 mm 对应哪种实物基座约定仍需图纸/安装定义确认。

真机无夹爪，因此增加显式法兰模型：在内存中移除 RG 子树，使 `tool0` 与 `wrist3_Link` 重合，保留作者腕部枢轴 `j4_anchor`。模型为六关节、零执行器、零相机，不修改原 RG 场景、默认姿态或相机。

初始关节和 IK rest bias 使用本次启动实测状态，避免目标偏置指向仿真归位；重新接合以有效实测反馈建锚。没有自动命令真机去仿真姿态。

有限反馈采样执行了 40 次查询，全部有效。主机设定 50 ms 周期，实际接收间隔约 36.93–63.16 ms；没有控制柜采样时间，不能把它叫作厂家反馈频率。

详细记录：[法兰数学对照与反馈检查](aubo_flange_and_follow_review_2026-10-19.md)。

## 5. 已完成的独立真机运动实验

以下运动均仅改变 J6；J1–J5 目标保持启动实测角。采用实验客户端速度 0.5°/s、加速度 1°/s²，均非厂家推荐参数；客户端回读也不独立证明物理硬限速。所有时间均为主机测量。

| 阶段 | 动作/请求 | 真机证据 | 结论与限制 |
| --- | --- | --- | --- |
| 静止停止接口 | 分别调用普通 stop 与慢停 | 普通 `robotMoveStop()` 返回 10001；`rootServiceRobotMoveControl(RobotMoveStop)` 返回 0，约 73 ms | 选定后续实测慢停路径；静止结果不替代运动停止 |
| 第一次微动 | 单次 +1°目标，中途慢停 | Follow 约 8.04 ms；慢停约 777.24 ms；后续只读实测约 +0.539°且停止 | 动作/慢停有证据；首次停后记录不完整 |
| 第二次微动 | 同样 +1°目标，中途慢停 | Follow 约 6.32 ms；慢停约 762.51 ms；实际约 +0.5502°，完整停后记录 | 该有限实验通过，现场确认附件正常 |
| 低频连续往返 | 21 条目标，0→+0.8°→0 | 全部成功，实际约 4.8 Hz，峰值约 +0.79988° | 连续接受目标并实际往返；不能单独判断队列语义 |
| 运动中替换目标 | 发 +10°，实测约 +3°时改回起点 | 改目标时约 +3.00889°，峰值约 +3.23986°后反向并返回 | 新目标在旧目标完成前生效；没有完整转满 10° |
| 10 Hz 设定 | 101 条目标，0→+2°→0 | 全部成功，实际平均约 9.43 Hz，峰值约 +1.99906° | 该序列通过，不是稳定 10 Hz 保证 |
| 20 Hz 设定 | 201 条目标，0→+2°→0 | 全部成功，实际平均约 16.19 Hz，峰值约 +1.99969° | 提高设定确实提高实际频率；仍有串行查询和写盘开销 |

这组实验已回答：当前柜子接受连续跟随位置目标，并非必须先到每个旧目标才响应下一条。运动中改目标可以改变轨迹。尚未回答：任意负载/频率的覆盖与积压边界、六轴协调表现、同实例 SDK 并发、通信断开时的停止。

微动首次丢失迟到查询结果的问题已修复：先保留原始返回和耗时，再标注验证失败或超预算；不能用空记录推断无异常。各实验原始报告保留，没有覆写成修复后的成功结果。

详细记录：[微动](aubo_j6_micro_trial_2026-10-19.md)、[低频序列](aubo_j6_sequence_test_2026-10-19.md)、[运动中改目标](aubo_j6_reversal10_test_2026-10-19.md)、[10 Hz](aubo_j6_sequence10hz_test_2026-10-19.md)、[20 Hz](aubo_j6_sequence20hz_test_2026-10-19.md)。

## 6. Quest 只读预览与手感确认

建立了只读专用入口，只加载不导出运动 API 的绑定，将真实反馈接到作者核心。复用原 WebXR、Relay、滤波、离合、腕部校准、目标管理和解耦 IK，默认 `world`，头显 yaw 不参与映射。独立线程接收输入，唯一控制循环修改核心，不在网络回调里求 IK。

实际头显测试观察到 Grip 释放、按下接合、候选改变和释放撤销。约 35 秒状态采样中，候选与实际关节最大差一度约 9.81°，操作者确认青色模型可见且移动；没有向机器人发送候选。

“Relay 已连接”与“右手柄有效输入”现分开诊断。已有一段缺手柄输入由操作者明确对应摘下头显，不能据此认定正常遥操掉流已定位或已解决。

额外 0.5°/s、5°/s 预览限速影响手感，因此默认恢复已验收仿真配置：200 Hz 核心计算，前三轴 150°/s、后三轴 180°/s 的仿真边界及原 IK 步长。操作者确认恢复后手感正常。这些预览配置不传给真机当运动速度；实体仍为 0.5°/s。

详细记录：[Quest 只读预览](aubo_quest_readonly_preview.md)。

## 7. Quest → J6 实体联调及故障修正

### 7.1 新增真实 J6 后端

保留只读入口，另建显式运动入口，避免网页或普通预览意外开放运动。原生 `J6Follower` 不导出通用六轴发送、startup、home 或清错方法。

后端串行持有 SDK，仅保留最新目标，不排队补发。独立 watchdog 可撤销主机发送许可，但不能中断正在等待的 SDK 调用，也不能绕过其串行锁独立发送物理 stop。

真机提交范围为启动角度到正向 +10°，仅 J6；有输入/候选/反馈失效、非 J6 偏移、跟随差值、目标步长和调用时效检查。故障后不保持 Grip 自动恢复；须停止确认、有效反馈以及新的释放/按下。严重故障本进程不允许恢复。

### 7.2 第一轮：发送链路接通，但原始故障原因缺失

18:50:45 启动，记录 13 次跟随提交。最后一次返回 0、约 11 ms；随后慢停返回 0、约 99 ms，反馈满足停止确认。用户感到“动了一下就退出”，实际是程序仍运行但进入锁定，不是 5 分钟到期。

接入层原有诊断缺口：故障后停止常规反馈轮询，随后反馈过期覆盖了最早原因。已增加首次停止触发、首次严重故障、相关年龄和在途操作记录，并写入状态转换日志。第一轮原始触发原因仍未知，不能用第二轮结果倒推。

### 7.3 第二轮：捕获到慢停预算误用

18:56:43 启动，记录 80 次跟随提交。末次请求偏移约 +2.548°，返回 0、约 10.883 ms；目标数和末次偏移不等于精确实测运动峰值。

首次停止触发明确为 `grip_released`。慢停仍在等待完成时，约 204 ms 后触发统一的 200 ms SDK 预算，严重故障锁定。慢停最终返回 0、耗时约 733.167 ms，SDK 日志报告进入停止状态。接入层因超预算跳过了后续反馈确认。

这是我们编写的停止时序处理问题。本次约 733 ms 与前期微动中约 762–777 ms 的慢停调用处于相近量级；先前证据不支持把慢停完成当作普通 200 ms 请求来处理。它也不能简单解释成网络断流或跟随返回错误。

用户确认静止、附件和线缆正常；关闭运动入口后，只读查询 4 次均报告停止，首末关节最大变化约 0.000212°。

### 7.4 最新修正：已离线验证，尚未实体复测

- 目标发送和普通查询继续使用 200 ms 实验预算。
- 慢停完成独立使用 2 秒试验预算，成功返回后再最多检查 2 秒反馈；不是厂家保证或物理制动时限。
- 慢停完成超预算仍锁定恢复；若之后返回成功，继续检查反馈，但不自动解除严重故障。
- 串行慢停期间反馈会变旧，不用旧反馈生成新锚点，也不把这件事反复伪报成新设备/输入故障。
- 重复 Grip 释放或故障消息不能把 `stopping`、`stop_unknown` 覆盖回 `stop_requested`；停止结果不明时不自动重试。
- 原生绑定已重新构建。没有改变作者算法、0.5°/s 实体速度、1°/s² 客户端加速度或运动范围。

详细记录与当前入口：[J6 跟随后端与现场记录](aubo_quest_follow.md)。

## 9. 当前参数与频率，必须分开理解

| 参数 | 当前含义 |
| --- | --- |
| 200 Hz | 作者核心/候选计算周期，不是控制柜接收率 |
| 10 Hz | J6 Quest worker 期望发送频率，不保证恒定达到 |
| 实测平均 16.19 Hz | 之前 20 Hz 设定的独立序列实验结果，不是当前 Quest 发送配置 |
| 0.5°/s | 当前实体目标限步长及 SDK 实验速度配置 |
| 1°/s² | 当前 SDK 客户端实验加速度配置 |
| 0..+10° | J6 相对本次启动锚点的命令范围，不是已完成的实际幅度 |
| 输入 250 ms、候选 100 ms | 主机时效检查 |
| 普通 SDK 请求/查询 200 ms | 试验延迟预算，超限撤销/锁定，不能中断调用 |
| 慢停完成 2 秒 + 反馈确认最多 2 秒 | 最新试验等待配置，不能当硬实时保证 |

这些是当前联调参数，不是正式六轴遥操的最终参数表。

## 12. 下一步顺序

1. 保持同一 J6 幅度/速度，复测“按 Grip 小幅跟随 → 松开停止 → 反馈确认 → 新释放/按下重新接合”，验证最新修正；不先提高速度或同时开放其他轴。
2. 在现有停止和反馈机制下安排可控输入暂停、参考空间变化和退出测试；通信断开或 SDK 并发停止须有明确的控制柜适用方案后单独验证。
3. 逐轴确认 J1–J5 方向、实际空间余量和模型定义，再实现并验证受限六轴发送。不能把 J6 试验当作整臂碰撞/奇异区验收。

5. 接入实体 RG/RS-485 时重新确认 TCP、负载和退出扭矩行为；然后加入相机和 LeRobot。默认录制关闭、数据落 `/data` 的约定继续保留。
