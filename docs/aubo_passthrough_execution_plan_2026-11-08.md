## 2. 执行顺序和阶段门槛

| 阶段 | 要得到的结果 | 进入下一阶段的条件 |
| --- | --- | --- |
| P0 现场状态与证据 | 确认实体停稳；固定源码、参数和已有数据版本 | 操作者确认实体停稳；旧控制会话不再持有运动任务，证据已保存 |
| P1 有线链路与阻塞位置 | 两端网口状态明确；需要的最小修复完成；明确还缺哪种时序证据 | 配置不存在已知不一致；有前后同窗口计数；未解决的通信问题有明确去向 |
| P2 透传执行层 | 明确接口契约和运动约束；完成离线实现与针对性验证 | 供点要求、限速/限加速度和断流处理均明确，离线验证通过 |
| P3 停止与保护 | 故障后仍可撤销；有条件地恢复只读停稳观测 | 不恢复运动许可；停止确认与结果不确定分支均通过离线验证 |
| P4 有限实机验收 | 从当前姿态保持到小幅轨迹，再接回VR | 链路、供点连续性、异响、松手停止和异常停止逐项通过 |

P1尚未定位的在途阻塞，允许在P2/P3离线工作并行准备后，用P4第一次受控保持阶段取得必要时序证据；不得因此直接进行自由VR遥操。静态资料或链路整改已足以排除某项时，删除对应实验。

## 3. P0：现场确认与固定版本

- **查清什么：** 实体是否已停止、旧SDK调用是否已返回、控制会话是否仍有运动任务。历史PID和故障状态只作线索，执行时重新读取，不能假定仍是同一进程。
- **如何做：** 先复用已保存状态和日志；现场确认停稳后正常结束旧会话。旧调用未返回或停止不确定时，不强杀后立即启动新控制进程、不自动清锁。
- **输出：** 本次执行目录、源码/二进制哈希、启动参数、变更前网卡/路由配置备份和现场状态记录。
- **存储：** 新数据、抓包和构建产物实际放在本机`/data/VR_teleoperation_runtime/`下独立目录；车载沿用已有runtime，不迁移现有项目。

## 4. P1：先查清有线链路和阻塞位置

### N1：100Mbps半双工从哪里来，两端是否一致？

**要回答：** 电脑实际PHY状态、控制柜端口速率/双工/协商方式、网线是否直连或经过中间设备；当前半双工是厂家要求、协商退化还是配置不一致？

**最小动作：** 读取eno1实际状态、驱动/PHY可用信息和NetworkManager配置；通过柜端可用界面/文档核对对端。只有确认存在中间设备才检查对应端口。缺少ethtool时，先用现有只读信息；需要其独有信息时再安装，不先堆工具。无法远程读取的柜端配置，列成具体现场待办，不能猜测补齐。

**修复边界：** 根据双方支持的方式匹配设置，一次只改一个因素；变更前备份，出现掉链或效果变差即恢复。不要单边强制全双工，也不把升级千兆作为目标。如果双方确实按厂家要求使用半双工，不能仅因half字样就判坏。

**完成证据：** 两端配置记录、实际生效状态、拓扑说明；存在并修复不一致时记录精确变更。无运动的短观测窗口记录开始/结束时间和错误/碰撞/重传增量，不能用累计计数判断修复效果；空闲无错误也不等于运动负载已通过。

### N2：535ms发生在SDK、网络交付还是控制柜应答等待？

**要回答：** 一次慢调用的请求何时实际发出、响应何时完整到达主机、SDK何时返回；A/B连接是否存在同一时间的重传或应答空档？

**先做：** 复用961次发送和17次停止的时间线，核对现有SDK实现/资料。只准备必要的分段计时和有限抓包配置，不再运行最小运动测速。

**只有仍需动态证据时：** 合并到P4第一次受控保持阶段，同一次会话记录SDK起止时间和两条已识别连接的TCP序号、重传、ACK及响应交付时间。登录后才开始有限抓包，避免记录登录凭据；不默认持续抓全流量或加入高频日志。若无法可靠识别请求/响应边界，就不能用任意PSH包间隔充当一次RPC的RTT。

| 观察结果 | 下一步 |
| --- | --- |
| 对应字节缺口、重传与慢调用对齐 | 沿物理链路/端口/传输交付处理；先不改运动算法掩盖通信问题 |
| 请求及时发出，响应明显迟到且无对应交付缺口 | 记录为“链路与柜端响应等待”；仅凭主机抓包不能进一步证明柜端内部模块 |
| 响应所需字节已到达，SDK仍长时间不返回，或请求迟迟未发出 | 再查SDK内部互斥、用户态等待和主机调度；此时才增加定向探针 |
| 字节边界/时间线不足以判断 | 精确列出缺失字段或厂家问题；不扩大成无目标工具排查 |

### N3：独立状态查询是否拖慢透传？

**要回答：** SDK是否支持当前多连接方式；A/B是否共享SDK内部资源；B的查询或冗余关节推送是否与约52ms慢峰有关？

**顺序：** 先看接口资料和N2时序，A/B同时慢只证明共同出现，不能直接判为锁竞争。只有仍无法选择架构时才增加一个单变量对照；优先只改变查询节拍或已确认非必需的冗余推送，不预先跑完整组合矩阵。

**禁止的对照：** 为得到“A单连接高频”而撤掉必需状态监测。若没有厂家支持的替代观测方式，就不能做无反馈运动对照，也不能把查询塞回发送循环。此时保留待确认项，先完成SDK/柜端兼容性核对。

**阶段产出：** 一页链路/通信结论：已修复什么、约52ms慢峰有何证据、尚未定位什么、是否有继续透传的可行路径。首轮有限采样以10–20秒为上限；未得到区分性证据时先复盘，不原样重复。有效变更后的对照最多补一轮，出现新原因才增加轮次。

## 5. P2：补齐真正的透传执行层

### M1：先明确接口契约与约束来源

必须记录：本柜端/固件推荐的送点周期与最大允许间隔、单点还是多点发送、欠载/积压行为、退出模式是否清除剩余点、失联与停止语义。优先用当前版本资料与已保存厂家代码；资料没有写明的列为厂家待答，不把旧示例5ms、猜测3帧缓存当事实。

关节速度/加速度上限来自可核验的厂家/柜端设置，实机调试再设置明确、保守的试运行限值。现有IK的150/180°/s不是透传试运行安全限值。若接口要求持续200Hz而现有链路只能供27Hz，该路径不能通过验收。

### M2：实现范围

- 保留现有VR映射、IK、最新目标槽和独立发送owner，不重写上层。
- 保留首帧实测保持；从该状态初始化执行参考位置/速度。
- 在**真正下发的相邻指令**之间约束速度、加速度；根据厂家契约决定是否需要jerk约束。滤波参数按时间定义，位置EMA不再承担轨迹规划职责。
- 通信大空档不能乘以巨大dt来允许追赶跳跃；停用旧意图，经停稳与新接合重新锚定。
- 只有已确认消费周期、队列清除和停止行为时才考虑有限短批量；不通过深队列、多运动发送线程或追赶补发来凑Hz。

**最小离线验证集：** 静止目标；目标阶跃与反向；5/50/250/535ms发送时间序列回放；进入/发送期间撤销；重新接合重置。逐项检查实际下发点约束、目标新鲜度、不重放旧轨迹和撤销不复活。复用本轮数据构造输入，只新增能覆盖上述缺口的测试；相关检查通过后不反复扩大回归范围。

**输出：** 约束参数及出处、执行层改动、对应离线结果。没有明确参数来源或接口契约时，完成离线框架后标记阻塞，不直接上机试错。

## 6. P3：保留保护，修复停稳确认路径

**保持：** 反馈200ms、SDK500ms保护和故障锁定；首帧/范围/输入校验继续有效，不通过放宽阈值消除中断。

**修复问题：** B超时后目前永久退出，造成停止ACK成功但再也拿不到新状态。运动许可撤销后，仅当旧调用已返回、SDK会话仍可用时，允许受控的只读停止观测继续；不与未返回调用并发复用对象，不自动重连，不恢复运动许可。无法获得有效反馈时继续保持`stop_unknown`。

**确认标准：** 退出/停止ACK与停稳结果分别记录；使用停止完成之后的新状态和新关节反馈，按现有静止判据确认。不使用停止前缓存或超时返回的数据冒充新确认。

**离线检查：** 重放最后一次535/527ms时间线；验证先撤销、迟到成功不重授权；可恢复观测时只确认停止；不能恢复时保持未知并明确提示现场确认。

## 7. P4：一次分级验收，不直接自由挥手

只有前置现场条件、接口要求、离线执行层和保护检查满足后才开始。全程由现场操作者掌握实体停止手段；每次异常即结束该阶段，不自动重试。

| 顺序 | 内容 | 必须记录/通过的内容 |
| --- | --- | --- |
| V1 | 从当前实测姿态进入，持续发送保持点 | 这是上机控制验收，即使目标不变也不称为无运动风险；若N2仍待答，同轮采最小所需时序证据。不能有未解释的长空档、保护中断或明显异响 |
| V2 | 单关节、限速限加速度的小幅轨迹 | 下发点满足约束，实测跟踪合理，无明显抖动；范围和速度来自M1，不沿用任意角度示例 |
| V3 | 接回Quest，小幅位置/姿态和反向动作 | 整套系统而非独立测试满足厂家供点要求；验证Grip松手、再接合、夹爪/录制开启后的行为 |
| V4 | 仅在前三项通过后延长会话 | 持续性与必要产品功能验收；短窗口通过不能表述为长期可靠性已证明 |

通过门槛：无新增错误/碰撞异常；实际供点满足已核实接口要求；没有未解释的长尾或状态过期；首点/运动约束有效；无明显异响；正常松手能取得新鲜停稳证据。若单点路径无法持续供点，形成“当前接口/链路不适合作为此遥操后端”的结论，停止继续抠毫秒，评估厂家支持的伺服接口或保留Follow。

## 8. 明确不做的工作

- 不重复1000点最小测速，不重算已经确认的首帧与Grip问题。
- 不重复“改10ms能否消除长尾”的旧实验；已有结果不支持该预测。
- 不同时开启QUICKACK、FIFO、CPU绑定、日志关闭再比较一个平均值。
- 不先调alpha、加大超时、关闭反馈或添加深队列来让界面少报错。
- 不仅凭约40–50ms就认定Nagle，也不凭step=3就认定缓冲深度。
- 没有磁盘阻塞或调度证据前，不扫描日志目录、调系统实时参数或换语言重写。
- 不在异常运动时追加试验；不把离线测试、rc=0、停止ACK或平均Hz当成实机平顺与停止的证明。

## 9. 每次执行只交付这些记录

每一步填写：**问题ID → 操作前状态 → 本次唯一变更/观测 → 证据路径 → 结论与局限 → 下一步/回滚**。区分“已证实、已排除、本窗口未观察到、待确认”，不把没有复现写成排除。

| 问题ID | 当前状态 | 下一步所需证据 |
| --- | --- | --- |
| N1 两端网口/拓扑 | 主机实际100M half/autoneg开；本轮新增迟碰撞、TX错误及TCP重传，链路需处理 | 柜端相连口配置、物理路径核对，两端匹配后以同窗口增量复核 |
