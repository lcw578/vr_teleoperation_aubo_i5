## 2. 法兰 FK 对照

### 2.1 对照基准和证据

示教器照片的坐标系选择为 `Base`，目标为 `Flange_center`。保存的关节角约为：

```text
J1        J2        J3         J4         J5        J6
10.341825 15.337400 135.963795 117.080903 86.690359 45.170022  deg
```

SDK FK 位置为 `(0.333294245, -0.068201684, 0.396920879)` 米，与示教器显示一致。图片和当前查询的对应见 `/data/VR_teleoperation_runtime/aubo-readonly-review-20261019.md`。

模型对照对象是 `wrist3_Link`，不是现有 RG 的 `tool0`。后者包含夹爪工具偏移，不能直接用于裸法兰。

现有模型肩关节原点高度为 `0.122 m`，SDK 登录输出的 DH 参数 `D1=0.0985 m`。模型来源：

- `assets/aubo_i5/scene_aubo_i5_rg.xml`；
- `ros2_ws/src/aubo_i5_teleop/urdf/aubo_i5_model.urdf`；
- 仓库内 AUBO description 的 i5 URDF 同样使用 `0.122 m`。

### 2.2 数学对应关系

用列向量齐次变换表示：

```text
T_sdk_base_flange = A × T_model_base_wrist3 × B
A = 沿 Z 平移 -0.0235 m，旋转为单位阵
B = 单位变换
```

原始模型比 SDK 的法兰 Z 高 23.5 mm，XY 和方向对应。显式加入上述基座换算后，对照了 38 组关节配置：1 组已保存的实测配置、1 组虚拟零角度、12 组虚拟单轴扰动、24 组固定随机种子的虚拟配置。

**这不是让机械臂运动到 38 个位置。** SDK 只做本地 FK 计算，虚拟关节角没有交给运动接口。换算后最大位置差约 `2.72e-16 m`，最大方向差约 `5.96e-8 rad`，表示两套数学模型在浮点数精度内相符，不能当作机器人定位精度。

这项结果支持当前关节顺序和模型的数学对应关系。23.5 mm 究竟对应哪种实物基座约定，仍须结合机械图纸/实物确定；不能据此自动修改安装高度、台面位置或障碍物坐标。本轮没有改仿真模型，也没有自动启用真机配置。

## 3. 有限反馈检查

报告：`/data/VR_teleoperation_runtime/aubo-feedback-readonly-20261019-162506.json`。

显式请求 40 次关节查询、主机周期 50 ms。40 次查询均返回 0 并通过反馈校验；39 个主机接收间隔约 `36.93–63.16 ms`，平均 `50.09 ms`；Get 调用耗时约 `4.56–18.88 ms`。登录和退出成功。

50 ms 是这次诊断主动设置的主机查询周期，不是控制柜反馈周期，也不是跟随接口推荐周期。没有控制柜采样时间或序号，不能证明每次读取都是新采样；不能从这组 Get 耗时推导 FollowMode 调用耗时。当前未注册持续回调，未开启持续 Logger。

## 4. 权限与停止：目前不能替控制柜做的推断

当前记录为 `online_mode=false`、`online_master_mode=true`。接口文档 §2.7.15 把后者的 true 描述为“联机主模式/手动模式”。两个字段不足以证明上位机已有运动权限；尚需核对这台柜子的手动/自动/远程控制设置和控制权。查询成功不等于取得运动控制权。本轮没有切换这些设置。

电脑库为 2.5.0，示教器界面显示 SDK 2.5.3，服务端版本为 `V4.5.111.71f2ee1-Alpha`。只读兼容已实测，运动兼容尚未实测，不因版本号不同自动更换库。

静态核查针对当前库，SHA256：

```text
a04ad0aa05b2d46fea5a863fe30698950e6434afeafd5a3eaf605c3f0df0ff1b
```

| 调用 | 当前能确认的事实 | 不能直接声称 |
| --- | --- | --- |
| `robotServiceFollowModeJointMove(q)` | MODEJ/TRACKING，客户端不等待到位，但同步等待请求响应 | 没有队列、任意频率可用、调用绝不阻塞 |
| `robotMoveStop()` | 本库静态路径选择 0x86，后续分派缺少对应分支，落入 10001 | 在本机运动中已复现；其他版本也有相同问题 |
| `rootServiceRobotMoveControl(RobotMoveStop)` | 0x59 分支存在，可构造停止请求 | 已证明能停止当前 FollowMode 并撤销目标 |
| `robotMoveFastStop()` | 0x5a 分支存在 | 等同硬件急停，或已验收其停止效果 |

配套 `robotmoveservice.h:238` 在示教接口注释中写明：“示教是通过运动模式的跟随模式实现的。所以subMoveMode＝TRACKING，跟随模式下调用stop,机械臂停不下来”。这是示教上下文，不能直接断言 FollowModeJointMove 必然停不下来；但不能忽略两者同用 TRACKING 的疑点。

PDF 第 59 页要求停止与 move 在不同线程，并阻止后续 move。当前只读绑定以 `io_` 互斥锁串行处理 SDK 调用；若直接沿用同一锁加入运动和停止，发送阻塞时停止也可能被堵住。释放 Python GIL 不能解除这个锁，同实例并发或另开连接是否受到支持仍需明确。

详细二进制证据和等待路径见 `/data/robot_SDK/analysis/aubo_follow_timing_stop_review_2026-10-13.md`。约 5 秒是异常请求响应超时路径，约 4 秒是某些停止通知等待路径，均不表示正常运动调用耗时或物理停住时间。

## 5. 独立跟随测试的具体顺序

以下是待实施的测试方案，不是现有可直接运行的运动命令。先不接 Quest，也不使用旧业务节点的启动、自动归位和点到点服务。

1. **确认适用接口和权限。** 获得当前版本 FollowMode 的停止/退出说明、并发支持方式和控制权设置；核对现场停止方式。先实现经过确认的停止路径，再开放有限运动入口。静止时调用停止只能验证返回路径，不能替代运动中停止验收。
2. **建立一次测试配置。** 指定测试关节、从实际反馈出发的允许区间、目标幅度、速度/加速度设置、提交周期、跟随误差和超时阈值、测试时长及停止判据。每项写明厂家依据或本次现场测试约束；未填写不启动，不猜默认数值。不自动修改柜内限位，也不把示教器 ±175° 与 Get 返回约 ±174.8998° 当成相同来源。
3. **从实测位置初始化。** 不先去 RG_READY，不开夹爪；确认没有其他运动命令所有者。首个待发送目标从有效实测关节构造，程序不因登录成功立即运动。
4. **单轴有限动作及停止。** 在已确认范围内做一次有限变化，核对关节顺序/方向和实际反馈；检验已确认停止路径，再逐步增加测试内容。不并发提交多个 follow 请求。
5. **连续目标与反向。** 同一发送任务仅保留最新目标，不积累历史目标；记录目标切换与实际反向响应，检查运行时间增长是否造成持续滞后。主机不排队不能证明控制柜不排队。
6. **中断与恢复。** 先测连接正常时停止提交和主动停止，再测经确认可开展的故障场景。在途请求撤销后仍可能被柜子接受，应单独标注结果。停止结果未知时锁住运动；故障后不自动恢复，须有效反馈及松开/重按 Grip。网络切断的运动测试须在通信丢失行为明确后单独安排。
7. **通过后再接 Quest。** 使用同一个真实 follower；验证实际状态锚定、正常释放、输入超时、参考空间改变、退出和再连接。相机、夹爪及 LeRobot 暂不进入本轮测试范围。

每次测试只保存有限报告，包含生成目标、实际提交目标、调用开始/结束、返回码、实测反馈及事件。主机单调时间与设备时间分开记录；未知设备时间不编造。Logger 继续默认关闭，报告保存在 `/data`。

## 6. 与作者保持一致和必须适配的部分

作者示例 `third_party/vr-teleop-kit/examples/teleop_bi_dk1.py` 经 `DK1Follower`/`BiDK1Follower` 发送关节位置；循环调用 `get_observation()`、核心 `get_action()`、`send_action()`。DK1 驱动是独立依赖，不能把示例当作 AUBO FollowMode 的停止或并发说明。

继续复用作者的滤波、离合、腕部校准、目标管理和解耦 IK，采用已经验收的 world 映射、关闭头显 yaw。不同之处集中在 AUBO 设备反馈、发送及停止，不重写另一套控制算法。

裸法兰接入需要一个显式模型配置：作者 IK 使用的 `tool0` 应对应所选择的真实法兰帧，而不是 RG 抓取点；保留作者腕部枢轴 `j4_anchor` 的 AUBO 几何定义。基座换算只在位姿坐标边界应用，不向关节角增加 23.5 mm，也不改作者求解公式。保留原 RG 仿真配置和相机。

首次真机不自动归位，但 IK 的 rest bias 仍是算法参数，须单独审核其取值；“从实测状态初始化”不等于自动消除 rest bias。当前 `AuboShadowCoordinator` 默认使用 RG，仍是假后端演练，不能直接解除 fake-only 限制接裸法兰。
